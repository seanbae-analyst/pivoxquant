## 1. The Deposition → **"Pre-Trade Checklist"** (안전 재설계)

### 1-A. 원본(위험) 버전 — 출시 불가
- AI 판사가 매도 클릭 시 3분 cross-examine
- "이유 약하니 재고하세요" 같은 평가성 발언
- Pause / Proceed / Withdraw 3택
- **리스크**: 자본시장법 §9①23 "투자권유"로 해석 가능 (매도 유보 권유)

### 1-B. 안전 버전 — 변호사 검토 후 출시 목표
유저가 **매도 버튼 클릭** → 7항목 체크리스트 모달 렌더:

| # | 체크 항목 | 응답 방식 |
|---|---|---|
| 1 | 매도 이유를 본인 언어로 2문장 이상 적었는가? | Y (유저 직접 입력) / N |
| 2 | 매수 당시 Thesis를 다시 읽었는가? | Y / N (Thesis 표시) |
| 3 | 손절가 / 익절가를 사전 설정했는가? | Y (해당 가격 표시) / N |
| 4 | 현재가가 그 가격대에 도달했는가? | 숫자 표시만 |
| 5 | 포트폴리오 비중 변화 예상치를 확인했는가? | Y / N |
| 6 | 최근 24시간 내 관련 뉴스 요약을 봤는가? | Y / N (뉴스 링크) |
| 7 | 본 거래가 "계획된 거래"인가 "반응적 거래"인가? | 본인 선택 |

**응답 완료 후**: "체크리스트 기록됨" 요약만 표시. **평가/판단 없음**. 버튼 2개: `체크 완료 → 매도 진행` / `나중에`.

### 1-C. 구현 경계 — DO / DON'T

| ✅ DO | ❌ DON'T |
|---|---|
| 유저 응답 기록 (Audit Trail) | AI가 응답 "약하다" 평가 |
| 기계적 템플릿 질문 (정해진 7개) | 동적 생성 cross-examine |
| Thesis/뉴스/가격 정보 표시 | "재고하세요" 같은 권유 |
| 유저가 직접 쓴 글 저장 | AI가 결정 방향 제시 |
| 체크리스트 **Skip 버튼 항상 활성화** | 체크 강제 |

### 1-D. 방어 문구 (화면 내 고정 표시)
- 상단: *"본 체크리스트는 투자 권유가 아니며, 유저의 자기 기록을 지원하는 도구입니다."*
- 하단: *"최종 결정은 유저 본인의 책임이며, 본 서비스는 결과에 대한 책임을 지지 않습니다."*

### 1-E. 변호사 질문 핵심 5개
1. 위 7항목 체크리스트가 자본시장법 §9①23 "투자권유"에 해당하는가?
2. "Skip 버튼 항상 활성화" + "평가 없음" 조건 하에서 유사투자자문업(§101) 신고 의무가 발생하는가?
3. 체크리스트 Yes/No 응답 자체가 "판단 개입"으로 해석될 여지는?
4. Thesis/뉴스/가격 **표시**가 "정보 제공" 경계를 넘어 "권유"로 미끄러지는 기준선은?
5. 동일 메커니즘을 **매수 클릭 시**에도 적용하면 리스크 감소하는가 (대칭 구조)?

## 2. Last Will Mode → **"Estate Planning Checklist + Education"** (안전 재설계)

### 2-A. 원본(위험) 버전
- "오늘 죽으면" 시뮬레이션 → 상속세 + 유언장 **초안 자동 생성**
- **리스크**: 변호사법 §109 (법률사무 대가 금지), 세무사업법 §6 (세무대리)

### 2-B. 안전 버전
유저가 Premium Plus에서 "Estate Prep" 활성화 →

1. **체크리스트 10개**: 상속인 명단 / 공제 한도 인지 / 유언장 작성 여부 / 변호사 상담 여부 / 부동산 소유 / 해외자산 여부 등
2. **일반 세율표 표시** (개인 계산 아님): 2026년 한국 상속세 5단계 세율 + 공제 한도표
3. **교육 카드 5장**: 상속세 기초 / 배우자 공제 / 일괄공제 / 가업승계 / 해외자산 특례
4. **외부 링크**: 국세청 상속세 계산기 / 대한변협 무료 상담 / 한국세무사회
5. **내 자산 Export**: CSV로 내려받기 → 본인이 변호사/세무사에게 전달

**AI는 유언장 초안 작성 절대 금지**. "이런 항목을 챙겨보세요" 안내만.

### 2-C. 구현 경계

| ✅ DO | ❌ DON'T |
|---|---|
| 체크리스트 제공 | 유언장 조항 작성 |
| 일반 세율표 | 유저 개별 세액 계산 |
| 교육 카드 | 특정 상황 자문 |
| 외부 전문가 링크 | 변호사/세무사 대체 암시 |
| CSV Export | 제출 대행 |

### 2-D. 방어 문구
- *"본 기능은 상속/유언 **일반 정보 교육**이며, 법률/세무 자문이 아닙니다."*
- *"구체 상속 설계는 반드시 변호사 / 세무사 상담이 필요합니다."*
- *"세율 및 공제 한도는 2026년 기준이며 법령 개정 시 달라질 수 있습니다."*

### 2-E. 변호사 질문
1. 상속세 일반 세율표 표시 + 교육 카드 제공이 세무사업법 §6 위반인가?
2. "유언장 초안" 대신 "유언장 준비 체크리스트"는 변호사법 §109 위반 소지가 있는가?
3. 유저 자산 CSV Export 제공이 "세무대리"로 해석될 수 있는가?
4. "국세청 계산기" 링크 제공은 안전한가, 아니면 우리가 직접 연결하는 행위 자체가 문제인가?
5. 기능 명칭 "Estate Planning Checklist"와 "Last Will Mode" 중 어느 네이밍이 법적으로 안전한가?

## 3. 양도세 추정기 → **"Tax Season Reminder + Education"** (안전 재설계)

### 3-A. 원본(위험) 버전
- 해외주식 매도 시점 최적화 AI 제안
- 250만원 공제 활용 맞춤 계산
- **리스크**: 세무사업법 §6 (세무대리)

### 3-B. 안전 버전
매년 4~5월 자동 **알림 배너**만 표시:

1. **리마인더**: "5월 해외주식 양도소득 신고 기간입니다"
2. **일반 공식 표시**: 양도차익 = 매도가 − 매수가 − 수수료, 세율 22%, 연간 250만원 기본공제
3. **예시 시나리오**: "연간 차익 500만 / 1,000만 / 2,000만 예시 세액" (일반 예시, 유저 개별 계산 아님)
4. **내 거래 내역 Export**: 연간 CSV 다운로드 (유저가 직접 홈택스/세무사 제출)
5. **외부 링크**: 국세청 홈택스 / 한국세무사회 / 유튜브 교육 영상

**유저 개별 세액 산출 금지**. 유저가 본인 거래 CSV를 내려받아 **외부 도구로** 직접 계산.

### 3-C. 구현 경계

| ✅ DO | ❌ DON'T |
|---|---|
| 일반 세율 공식 표시 | 유저별 예상 세액 자동 산출 |
| 예시 시나리오 (익명) | "당신은 X원 납부 예상" |
| 거래 내역 CSV | 홈택스 자동 제출 대행 |
| 교육 콘텐츠 | 세무 절세 자문 |
| 신고 기간 리마인더 | 신고 대행 |

### 3-D. 방어 문구
- *"본 기능은 해외주식 양도소득 **일반 교육**입니다."*
- *"실제 세액은 본인 거래 내역으로 **홈택스** 또는 **세무사 상담**을 통해 확인해야 합니다."*
- *"세율 및 공제는 2026년 기준이며 법령 개정 시 달라질 수 있습니다."*

### 3-E. 변호사 질문
1. 일반 세율표 + 예시 시나리오 표시가 세무사업법 §6 "세무대리"에 해당하는가?
2. CSV Export 제공이 "세무 자료 작성" 대리로 해석될 여지가 있는가?
3. "5월 신고 기간 리마인더" 자동 푸시가 세무대리 알선으로 해석될 가능성은?
4. 유저 거래 내역에 **세액 추정 컬럼을 자동 추가**하는 것은 어디까지 허용되는가?
5. "세무사 매칭 서비스" (외부 세무사 연결 플랫폼) 연동은 가능한가?

## 4. Confession Booth → **"Private Journal (E2E Encrypted)"** (안전 재설계)

### 4-A. 원본(위험) 버전
- "Confession" 프레임 — 종교적 고해성사
- 음성 녹음 + AI 응답
- **리스크**: 개인정보보호법 §23 민감정보 처리

### 4-B. 안전 버전
**종교 프레임 완전 제거**. 재포지셔닝: **"Private Trading Journal"**

1. 텍스트 기반 private notes (음성 녹음 **삭제**)
2. **E2E 암호화** (유저 기기 로컬 키) — 서버는 암호문만 저장, 복호화 불가
3. AI 응답은 **세션별 휘발** (DB 저장 0) — 유저가 요청 시에만 로컬 cache
4. 민감정보 수집 **목적 없음** 명시 (투자 감정 기록 ≠ 민감정보 분류)
5. 약관: "서버는 기록의 암호문만 보관, 복호화 불가. 분실 시 복구 불가."
6. 유저가 삭제 요청 시 암호문 **즉시 삭제**

### 4-C. 구현 경계

| ✅ DO | ❌ DON'T |
|---|---|
| E2E 암호화 텍스트 저널 | 음성 녹음 수집 |
| 세션별 휘발 AI 응답 | AI 응답 영구 저장 |
| 유저 로컬 키 관리 | 서버 키 보관 |
| 삭제권 즉시 실행 | 백업 유지 |
| 민감정보 수집 목적 부재 | 감정 분석 + 마케팅 활용 |

### 4-D. 방어 문구
- *"본 기능은 유저 본인의 사적 기록을 위한 E2E 암호화 공간입니다."*
- *"서버는 암호문만 저장하며 **복호화 기능을 가지지 않습니다**. 분실 시 복구 불가."*
- *"AI 응답은 세션 종료 시 폐기되며 개선/마케팅 목적으로 활용하지 않습니다."*

### 4-E. 변호사 질문
1. "투자 관련 감정 기록"이 개인정보보호법 §23 민감정보에 해당하는가?
2. E2E + 서버 복호화 불가 구조에서 PIPA §23 동의 요구 수준은?
3. AI 응답 세션별 휘발(저장 0)이 실제로 입증 가능해야 하는 기술적 증거 요구는?
4. "Confession" 네이밍이 종교 차별 소송 리스크 있는가, 아니면 문화적 비유로 OK인가?
5. 유저 삭제 요청 시 백업/로그에서 완전 삭제 의무 수준은?

## 5. HRV Gate → **"Trading Readiness Self-Check"** (안전 재설계)

### 5-A. 원본(위험) 버전
- Apple Watch HRV 자동 연동
- "공포 매도 확률 73%" 경고 표시
- **리스크**: 의료기기법 §2 무허가 의료기기

### 5-B. 안전 버전
HealthKit/Apple Watch 연동 **완전 제거**. **자기 입력 자기체크**로 전환:

1. 매매 세션 시작 전 **3문항 자기 입력**:
   - 수면 시간 (직접 입력 시간 수)
   - 오늘 컨디션 (1~5 slider)
   - 집중도 (1~5 slider)
2. **결과는 "참고 표시"만** — 판단/경고 없음
3. 본인 기록 누적 → 주간/월간 패턴 그래프 (본인 데이터만)
4. "의료기기 아님" 고정 배너

**생체 센서 데이터 수집 0**. 주관적 자기평가만.

### 5-C. 구현 경계

| ✅ DO | ❌ DON'T |
|---|---|
| 유저 자기 입력 3문항 | HealthKit / Wearable 센서 연동 |
| 참고 표시 (무판정) | "매도 자제 권고" 경고 |
| 본인 이력 그래프 | "정상/비정상" 라벨 |
| "의료기기 아님" 고지 | 질환 명 거론 |
| 옵트인 기본 OFF | 진단 / 예측 용어 사용 |

### 5-D. 방어 문구
- *"본 기능은 **의료기기가 아니며** 질병의 진단/예방/치료 목적이 아닙니다."*
- *"제공되는 정보는 유저 본인의 **주관적 기록**이며, 의학적 판단의 근거로 사용할 수 없습니다."*
- *"건강 관련 우려가 있는 경우 반드시 의료진 상담을 권합니다."*

### 5-E. 변호사 질문
1. 자기 입력 기반 "readiness check"가 의료기기법 §2 "의료기기" 정의에 해당하는가?
2. HealthKit **연동 없이** 자기입력 3문항만으로 의료기기법 리스크 해제되는가?
3. "1~5 slider 결과 표시"가 "진단" 또는 "평가"로 해석되지 않으려면 어떤 문구가 필요한가?

## 6. Personal Agent → **"Personal Journal Companion"** (안전 재설계)

### 6-A. 원본(치명 위험) 버전 — 출시 절대 불가
- 유저 한 명당 AI Agent 전담 배치 (Personal Analyst)
- 장기 메모리 기반 매매 분석/예측/조언
- "이 종목 지금 사야 한다", "손절가는 X원"
- **리스크**: **본격 투자자문업** 해석 가능성 60%+. 자본시장법 §6② + §9 + §101 정면 위반. 금융투자업 면허(자본금 5억+) 없이 불법

### 6-B. 안전 버전 — "Journal + Mirror + Question" 3역할만

#### 허용 동작
| 역할 | 예시 응답 |
|---|---|
| **기억 (Memory)** | "2 months ago, when you bought NVDA, your stated reason was FCF growth + data center momentum. That is the record." |
| **미러 (Mirror)** | "Historically you tend to sell after 3-day -2%+ drawdowns. Today's drawdown is -1.8% over 2 days." |
| **IPS 알림 (Self-covenant reminder)** | "Your declared Investment Policy Statement limits single-position weight to 15%. This trade would put NVDA at 18.2%." |
| **질문 (Question only)** | "What specifically about this situation differs from when you bought in March? Your record does not answer that." |
| **Summary (factual)** | "This month: 12 trades, avg hold period 18 days, 9 journaled decisions / 3 unexplained." |

#### 절대 금지 동작
- ❌ "Buy / Sell / Hold" (어떤 형태로도)
- ❌ 종목 분석 / 예측 / 목표가 / 손절가 제안
- ❌ 논거 평가 ("이 논리는 약하다/강하다")
- ❌ 시장 방향 의견 ("이번 주 하락 예상")
- ❌ 포트폴리오 구성 제안 ("섹터 분산 필요")
- ❌ POSITIVE/NEGATIVE/NEUTRAL 라벨 (이건 공용 AI 영역)
- ❌ "recommend / suggest / should / advise / advice / 권장 / 추천 / 조언 / 유망"
- ❌ 새로운 팩트 주입 (뉴스/실적/가격 해석)

#### 기술 구조
```
System prompt HARD rules:
- You are a journal companion, NOT a financial advisor.
- You may only: remember, mirror, ask questions.
- You may NOT: suggest, predict, evaluate, recommend.
- If user requests advice: respond "I can't advise. I can only check your record against current behavior."
- Refuse novel fact injection (news, prices, earnings).

Output Gate (서버측 정규식 재필터):
- 89 regex + "자문성 발언" 확장 regex 20개
- 위반 시 응답 버림 + 로그 + "I can only mirror your record." 폴백

Memory:
- User-owned, E2E optional
- Retention: 12 months default, user can delete anytime
- No cross-user pattern extraction
- 민감정보 (감정/심리) 분리 저장, 별도 동의
```

#### 옵트인 + 고지
- Premium/Premium Plus 진입 시 별도 동의 화면
- "This AI does not give investment advice. It only remembers your own records and asks questions." 고정 배너
- 매 세션 시작 시 1줄 disclaimer

### 6-C. 구현 경계 (DO / DON'T)

| ✅ DO | ❌ DON'T |
|---|---|
| 유저 과거 Journal 되돌려주기 | AI가 새로운 해석 추가 |
| 행동 패턴 통계 (hold period, turnover) | 패턴 기반 매매 제안 |
| IPS 위반 사실 알림 (숫자 기반) | IPS 위반 여부 판단 ("이건 위반") |
| 유저가 적은 논리 그대로 인용 | 유저 논리 요약/재해석 |
| 질문 (What/How/When) | 제안 (Should/Must/Do) |
| 월간 거래 요약 (사실 나열) | 월간 성과 평가 |
| Pre-Trade Checklist와 연동 (유저가 답 작성) | Agent가 체크리스트 대신 작성 |

### 6-D. 방어 문구 (매 응답 하단 고정)

- *"모든 매매 결정과 그 결과에 대한 책임은 유저 본인에게 있습니다."*

### 6-E. 변호사 질문 5개 (Q7~Q11 — 기존 1~5 이후 추가)

**Q7**. Agent가 유저 과거 Journal 원문을 **그대로 인용**해 되돌려주는 행위(mirror)가 자본시장법 §9 투자자문에 해당하는가? 저작물 복제 vs 자문 제공의 경계는?

**Q8**. IPS 위반 사실을 **숫자 기반으로 알림**하는 행위(예: "포지션 15% 한도 → 현재 18%")가 "권유"인가 "정보 제공"인가? 유저 본인이 작성한 IPS에 대한 사실 확인 알림이어도 저촉?

**Q9**. Agent의 system prompt에 "recommend/suggest 금지"를 하드코딩하고 output gate로 2차 필터링하는 이중 구조가 **유사투자자문업(§101) 범위로 신고**하면 커버 가능한가? 아니면 **본격 투자자문업 면허** 필수?

**Q10**. 유저가 "이 종목 어때?" 직접 요청했을 때 Agent가 **"나는 답할 수 없다"**라고 거부하는 설계가 면허 의무 회피 요건 충족하는가? 매 거부를 로그에 남겨야 하는가?

**Q11**. Agent memory에 유저 **감정/심리/자신감 지수**를 저장하는 것이 개인정보보호법 §23 민감정보인가? 일반 개인정보인가? 동의 양식 수준은?

### 6-H. 개인정보 특별 방어선 (CEO 지시: "개인정보 특히 조심해서")

PIPA + GDPR 이중 준수. 한국 유저뿐 아니라 해외 유저(EU/미국) 접속 시 강화 적용.

| 원칙 | 구현 |
|---|---|
| **Data Minimization** | 수집 항목 **하드 화이트리스트**. 감정·심리 수치는 **유저 명시 재동의** 없으면 수집 금지. 온보딩 20문항 외 수집 항목 추가는 별도 PIA(영향평가) |
| **Local-first Memory** | Agent memory 기본 **유저 기기 IndexedDB**. 서버 동기화는 옵트인. **서버 복호화 불가**한 E2E 구조 (유저 passphrase 기반 AES-GCM). 서버는 암호문만 보관 → PIPA "처리자" 지위 완화 |
| **가명화 디폴트** | 서버 저장 필요 최소 데이터는 자동 가명화: `user_id → sha256 hash`, `거래액 → bin(0~10M/10M~100M/…)`, `종목 → sector bucket` |
| **Retention 30일** | 기본 **30일 후 자동 삭제**. 유저가 명시 연장 요청해야 12개월 유지. Purge job은 daily cron + audit log |
| **Purpose Limitation** | agent memory는 **본인 응답 생성 외 용도 금지**. 마케팅 분석/모델 개선/통계 일절 사용 안 함 (별도 옵트인 없이). 타 유저 profiling 절대 금지 |
| **민감정보 분리** | 감정/심리 데이터는 **별도 encrypted table** + 별도 접근 권한 + 별도 보존정책. 메인 trade_history와 분리 |
| **유저 완전 삭제권** | 한 번 클릭 → 30일 내 모든 backup/log 포함 물리 삭제. GDPR Right to Erasure 수준 |
| **Data Export** | 언제든 CSV/JSON export 가능 (portability) |
| **국외이전 최소화** | Anthropic Claude API 경유는 불가피하나, **pseudonymized payload만** 전송 (실명/계좌번호/이메일 제외). Transfer Impact Assessment 문서화 |
| **Breach Notification** | 침해 의심 72시간 이내 유저 고지 + 개보위 신고 |
| **No Marketing Profiling** | PIPA §23 민감정보 profiling 금지. 광고 타겟팅 / 리텐션 세그먼트 / A/B 실험 대상 제외 |

### 6-I. "꼼수의 꼼수" 10개 — 법 테두리 내 창의적 회피 구조

CEO 지시: "꼼수의 꼼수를 잘 찾아봐야 해". 로펌에 모두 검증 요청할 항목.

| # | 전략 | 핵심 논리 | 로펌 질문 |
|---|---|---|---|
| 1 | **Journal = 유저 UGC 프레이밍** | "유저가 작성한 글만 저장/재표시. AI는 새 정보 생성 안 함 = 자문 아님" | 과거 UGC 재구성이 "자문" 해석 범위인가? |
| 2 | **Local-first Memory** | Memory를 서버에 저장 안 함. 유저 기기에만 → "처리자" 지위 회피 | Claude API 경유 transient 처리는 "처리자"로 분류되나? |
| 3 | **자기 대화 프레이밍** | 모든 output = "You might ask yourself…" 형식. AI는 유저 자기 질문 도구 | 대명사 2인칭 사용이 자문성 약화 요건 충족? |
| 4 | **Attribution 역전** | AI output = 유저 과거 발화의 **재조합**. AI는 편집자, 저자 아님 | 재조합(compilation) vs 창작(generation)의 법적 구분 기준은? |
| 5 | **한정 어휘 템플릿** | AI는 사전 등록된 문장 템플릿에서만 선택 (자연어 자유 생성 금지). 20~30개 템플릿 | 템플릿 기반 응답이 비결정적 자연어 응답 대비 규제 회피 가능? |

| 7 | **Output Gate 이중 필터** | 89 regex + "자문성 발언" 패턴 20개 전수 차단 | 필터 통과 대비가 업무 표준으로 인정되는 수준은? |
| 8 | **옵트인 2중 구조** | Premium Plus 진입 시 1차 동의 + 매 세션 시작 시 1줄 재확인 | "재확인" 구조가 "충분한 고지" 법적 기준 충족? |
| 9 | **약관 면책 3중** | (a) 약관 본문 (b) 매 화면 배너 (c) 매 응답 푸터. 3중 고지 | 어떤 조합이 면책 인정 받기 유리한가? |
