# PivoxReport — 내 토스증권 계좌를 read-only 로 읽어 거울 리포트 만들기

> 2026-09-10 작성. 대상은 **운영자 본인 계좌 하나**다. 유저용 브로커 연동이 아니다.
> `BROKER_LINKING_AVAILABLE=false` 는 그대로다 (사유: `frontend/src/app/(auth)/onboarding/broker/page.tsx` 주석).

## 왜 이게 되는가, 왜 유저용은 안 되는가

| | 본인 계좌 (이 문서) | 다른 유저 계좌 |
|---|---|---|
| 키 소유 | 운영자 본인 → 본인 서버 env | 유저가 우리 서비스에 붙여넣기 |
| 토스 약관 §5② (앱키 제3자 대여·양도·누설 금지, 접근매체) | 토스가 "ChatGPT·Claude 에 키 연결" 을 직접 홍보한 것과 같은 범주 | **유저가 자기 증권사 약관을 어기게 만드는 구조** — 변호사 답 전엔 보류 |
| scope | 없음 — 조회 토큰으로 주문도 됨 | 동일. 우리가 유저의 주문 가능 자격증명을 보관하게 됨 |

시세 관점의 의미: PivoxQuant 에서 시세가 필요한 화면은 `/portfolio` 평가액뿐이다.
평가액을 유저 본인 계좌에서 받으면 FMP §2.2.2 와 R7 이 함께 닫힌다 (CLAUDE.md §제품).
이 스크립트는 그 경로의 첫 실증이다 — 단, 아직 운영자 1명에 한해서.

## 준비 (1회)

1. 토스증권 **PC 웹(WTS) 로그인 → 설정 → Open API** 에서 `client_id` / `client_secret` 발급.
2. 같은 화면의 **허용 IP** 에 이 스크립트를 돌릴 머신의 공인 IP 등록.
   REST 도 허용 IP 가 적용된다 — 빠지면 403 `edge-blocked`.
3. `.env` 에 추가 (`.env.example` 의 TOSS 블록 참조):
   ```
   TOSS_CLIENT_ID=...
   TOSS_CLIENT_SECRET=...
   ```
   Render 에는 넣지 않는다. 서버가 읽을 이유가 없고, 주문 가능한 자격증명을 서버에 두는 것이다.

## 실행

```bash
./venv/bin/python scripts/pivox_report.py                # 이력 730일 + 최근 90일 거울 → reports/personal/pivox_report_<날짜>.md + .json
./venv/bin/python scripts/pivox_report.py --since 1500   # 첫 줄이 "일치"가 아니면 이력을 더 넓혀서
./venv/bin/python scripts/pivox_report.py --days 30
./venv/bin/python scripts/pivox_report.py --dump-raw /tmp/raw.json   # 응답 원본 보관 (계좌번호 원문 포함, 토큰 없음)
./venv/bin/python scripts/pivox_report.py --from-raw /tmp/raw.json   # 네트워크 없이 재렌더
```

`reports/personal/` 은 gitignore 다. 같은 이름의 **`.html`** 도 함께 떨어진다 — 브라우저로 열면
보유 비중·손익 막대, 경로 타임라인(매수 ▲ 매도 ▼), 거울 두 열이 그려진다. 서버 없음, 단일
파일, 스크립트 없음. 디자인 토큰은 v3 그대로 (`services/toss/html_report.py` 상단).

## 리포트 구성 (v3, 2026-09-10 — v2 에 종목 축을 더함)

첫 실행에서 본 것: 이 계좌의 이야기는 잔고가 아니라 **경로**에 있었다. 보유 9종목 중 6종목은
90일간 손대지 않았고 손실이 거기 몰려 있었으며, 체결은 두 종목에 몰려 있었다. 잔고 표는
그걸 말하지 못한다. 그래서 v2는 주문 이력 전체(`--since`, 기본 730일)를 받아 포지션을
되짚고, **제품이 `/journal` 에서 쓰는 거울 함수 그대로**를 이 계좌에 댄다.

| 절 | 내용 | 계산 주체 |
|---|---|---|
| 이 리포트가 딛고 선 이력 | 되짚은 수량·평균단가가 토스 잔고와 **일치하는가**. 불일치 종목과 사유 | `services/toss/history.py::reconcile` |
| 평가 | 평가액·매입·미실현·**실현 누계(수수료·세금 차감)** | 토스 응답 + 재구성 |
| 거울 — 최근 N일 / 전체 이력 | 회전(체결 수·거래대금·보유일) · 추가매수(평균단가 대비 아래/위/같음) · 손익처분(이익 실현 vs 손실 실현의 보유일·수익률 중앙값) | 전체 = `services/behavior/{turnover,averaging_down,profit_loss}_mirror` 그대로 / 최근 = 전체 이력 취득단가 위에서 창만 제한 |
| 집중 | 종목 수 · 가장 큰 종목 비중 · 30% 선 · 국내/해외 | 평가액 가중 |
| 보유 종목의 이력 | 보유 시작일 · 보유일 · 매수/매도 횟수 · 마지막 체결 · 평단 · 비중 · 손익률 | 재구성 |
| 떠난 종목 | 완전히 정리한 종목의 실현손익·매도 수익률 중앙값 | 재구성 |
| **종목 하나하나** (v3, 2026-09-10) | 종목당 카드 한 장: **평단 궤적** + 매수/매도 시점 + 추가매수가 평단 위였는지 아래였는지 + 그 종목만의 승률·중앙값 + 실현/미실현/합계 | `services/toss/analysis.py::per_symbol` |
| 이 숫자가 말하지 않는 것 | 예수금 부재 · 표시환율 · Open API 미지원 호가 · 세후 차이 | — |

**"일치"가 먼저다.** 실현손익은 취득단가가 맞을 때만 의미가 있다. 리포트 첫 줄은 되짚은 수량·
평균단가를 토스 잔고와 대조한 결과다. 안 맞을 때 **두 축으로 나눠 진단한다** — 수량과 취득원가를
따로 보기 때문에 원인이 갈린다:

| 진단 (`kind`) | 뜻 | 실현손익 |
|---|---|---|
| `share_count_changed` | 수량이 다른데 **취득원가 총액이 일치**하거나, **직전 전량매도 뒤 0주에서 다시 열리는 것을 관측**했다 — 어느 쪽이든 빠진 매수가 없다는 뜻이고, 병합·분할·합병 전환으로 주식 수만 다시 쓰인 것이다 | **그대로 신뢰 가능.** 그 포지션이 열린 뒤 매도가 있었으면 그 건만 다른 눈금일 수 있다고 함께 적는다 |
| `fractional_dust` | 취득 기록 없이 판 주식이 **한 주 미만** — 소수점 거래 반올림 찌꺼기 (실계좌 예: TSLA 0.0244주 = $8.33) | 영향 없음 |
| `quantity` | 수량도 취득원가도 다르고, 포지션이 열리는 것도 못 봤다 | 취득단가가 틀렸다 |
| `absent` | 보유 중인데 이력에 체결이 하나도 없음 | 〃 |
| `unmatched_sales` | 취득 기록 없이 판 주식이 **한 주 이상** | 그 몫은 **0 으로 빠져 있다** — 부풀리지 않는다 |
| `average` | 수량은 맞는데 평균단가가 다름 | 취득단가가 틀렸다 |
| `ghost` | 이력상 보유인데 계좌엔 없음 | 이력 밖 매도·출고 |

⚠️ **심볼의 첫 체결이 매수인 것은 "포지션이 여기서 열렸다"는 증거가 아니다** — 창이 늦게
시작해도 똑같이 보인다. 그래서 `opened_from_observed_zero` 는 **우리가 처리한 매도로 0에
도달한 뒤 다시 산 경우에만** 참이다. 이 구분을 안 하면 창이 잘린 종목을 "주식 수 변경"으로
오진한다 (테스트로 고정돼 있다).

`share_count_changed`·`fractional_dust` 만 있으면 리포트는 실현손익을 깎아내리지 않고 "전체"로
표시한다. 나머지가 하나라도 있으면 "부분"으로 표시하고 종목 이름을 붙인다. `--since` 를 넓혀
닫히는 것은 `absent`·`quantity`·`unmatched_sales` 뿐이고, `share_count_changed` 는 넓혀도 안
닫힌다 (Open API 에 그 이벤트 자체가 없다). 억지로 맞추지 않는다.

**실계좌 실측 (2026-09-10, `--since 1000`)**: 불일치 3건이 전부 이 무해한 쪽이었다 — ABTC 는
16.09:1 주식 수 변경, TSLA·NVDA 는 소수점 잔여 $8.33 / $0.07. 그래서 실현손익 ₩5,133,052 는
"전체" 로 표시된다. 이 구분을 넣기 전에는 셋 다 "이력 밖의 매수" 로 오진하고 실현손익을
"부분" 으로 깎아내리고 있었다.

**v3 가 더한 것 — 종목 축 (2026-09-10).** v2 까지 리포트는 계좌 전체만 가로질렀다. 승률도
보유기간 비대칭도 체결 리듬도 전부 "나는 어떻게 매매하는가" 였고, 종목 이름이 나오는 자리는
"그 종목에서 얼마 벌었나" 뿐이었다. 데이터는 이미 `history.py` 가 들고 있었다 —
`BuyOutcome.relation` 이 매수 한 건 한 건을 그때 평단과 비교해 두고, 이제
`avg_cost_after` 가 그 매수가 평단을 어디로 옮겼는지까지 기록한다. 카드는 그걸 그린다.

증권사 앱은 **지금** 평단만 보여준다. 그게 어떻게 거기까지 왔는지는 안 보여준다. 내려가는
계단이면 평단 아래에서 계속 샀다는 뜻이고, 올라가는 계단이면 오를수록 더 샀다는 뜻이다.
선이 끊긴 자리는 전량 정리했다가 다시 들어간 자리이고, 그 간격(일)이 카드에 적힌다.

카드는 **보유 종목 전부 + 정리한 종목을 기여 절댓값 순으로**, 최대 16장(`_CARD_CAP`).
잘린 종목 수는 캡션에 적고 원장 표에 그대로 남는다.

⚠️ 그림 폭 **300 유닛은 고정값이다.** A4 한 단(695) − 판 들여쓰기(34) 을 반으로 나누고
거터 절반을 뺀 316 안에 들어가야 한다. WeasyPrint 는 viewBox 가 있는 SVG 를 **고유 폭으로
배치한 뒤 셀에 맞춰 자른다** — 줄여 그리지 않는다. 300 보다 넓게 만들면 화면에선 멀쩡한데
**PDF 에서만** 오른쪽 숫자가 잘린다.

⚠️ **WeasyPrint 는 문서 스타일시트를 `<svg>` 안에 적용하지 않는다.** `svg text { font-size }`
· `svg .fig { fill }` 는 전부 화면 전용이고, PDF 에선 16px 검정 기본값으로 그려진다(그래서
viewBox 밖으로 나가 잘렸다 — v2 까지 8개 차트 전부 이 상태였다). `_typeset()` 이 렌더 직전에
각 `<text>` 에 폰트·크기·색을 직접 박는다. 색은 **인라인 style** 로 박아야 한다 — presentation
attribute 는 스타일시트의 클래스 규칙에 진다.

**v1 에 있었고 v2 에서 뺀 것**: HHI, 평가액 대비 거래대금 비율, "물타기" 라는 단어. 제품
거울은 개수·일수·수익률만 내고 사람을 채점하는 지수는 내지 않는다 (DECISIONS.md — AI 점수화
폐기). 이 리포트도 그 선을 따른다.

없는 것 — 응답에 없어서 만들지 않은 것:
- **예수금** (holdings 는 KR·US 주식만) → "평가액"은 주식 평가액이다
- 시간외단일가 등 Open API 미지원 호가로 낸 주문 — 이력 불일치의 흔한 원인
- 다음에 뭘 하라는 문장. 거울이지 조언이 아니다 (자본시장법 경계는 여기서도 같다)

## 안전장치 — 어디에 있고 무엇을 막는가

- `services/toss/client.py::READ_ONLY_PATHS` — GET 허용 경로 9개. 그 밖의 경로는
  **요청 전에** `TossReadOnlyViolation`. 주문·정정·취소·조건주문·매수가능금액은 목록에 없다.
  테스트: `tests/test_toss_readonly_client.py` (denied path 7종이 소켓을 열지 않음을 확인).
- 토큰은 메모리에만 있다. 디스크에 쓰지 않는다. 로그는 `redact()` 를 거친다.
- 토스는 **client 당 유효 토큰 1개**다. 두 프로세스가 같은 client 로 돌면 서로 무효화한다.
  cron 에 넣을 거면 하나만.
- 계좌번호는 출력에서 마스킹된다 (`***8901`). `--dump-raw` 파일에는 원문이 들어간다.
