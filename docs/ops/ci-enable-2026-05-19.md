## §1. 사전 요건 — GitHub Secrets 등록 (CEO 액션)

### 1-1. GitHub 저장소 진입

1. https://github.com/seanbae-analyst/pivoxquant 열기
2. **Settings** 탭 (저장소 상단 우측)
3. 좌측 사이드바 → **Secrets and variables** → **Actions**
4. 우측 상단 → **New repository secret**

### 1-2. 등록할 secret 3종

#### (a) `RAILWAY_BACKEND_URL`

| 항목 | 값 |
| ---- | -- |
| Name | `RAILWAY_BACKEND_URL` |
| Secret | `https://web-production-7b484b.up.railway.app` |

> Railway 대시보드에서 실제 URL 변경 시 즉시 갱신할 것.
> trailing slash (`/`) 포함하지 말 것.

#### (b) `SLACK_WEBHOOK_URL`

| 항목 | 값 |
| ---- | -- |
| Name | `SLACK_WEBHOOK_URL` |
| Secret | `https://hooks.slack.com/services/T.../B.../xxxx...` |

> §2 절차로 먼저 webhook 생성 후 여기에 입력.

#### (c) `WEEKLY_MEMO_TRIGGER_SECRET`

| 항목 | 값 |
| ---- | -- |
| Name | `WEEKLY_MEMO_TRIGGER_SECRET` |
| Secret | 32-byte hex (아래 명령으로 생성) |

생성 명령 (로컬 terminal):

```bash
openssl rand -hex 32
```

> 출력값을 GitHub secret 에 저장하고, **반드시 Railway env 에도 동일 값으로** 등록할 것
> (`railway variables --set WEEKLY_MEMO_TRIGGER_SECRET=<value>`).
> 두 곳이 일치해야 weekly-memo workflow 가 백엔드 API 호출 시 HMAC 검증 통과.

## §2. Slack Webhook 생성 (CEO 액션, 약 5분)

1. https://api.slack.com/apps 접속 → 본인 계정 로그인
2. **Create New App** → **From scratch**
3. 입력:
   - App Name: `pivoxquant-bot`
   - Workspace: 본인 workspace 선택
4. 좌측 사이드바 → **Features** → **Incoming Webhooks**
5. 우측 토글 **Activate Incoming Webhooks** → ON
6. 하단 **Add New Webhook to Workspace**
7. 채널 선택 (권고: `#pivoxquant-ops` 같은 운영 전용 채널 — 미존재 시 Slack 에서 먼저 생성)
8. **Allow** → Webhook URL 발급됨 (`https://hooks.slack.com/services/T.../B.../xxxx...`)
9. URL **Copy** → §1-2(b) `SLACK_WEBHOOK_URL` secret 에 붙여넣기

> Slack workspace 가 없다면 https://slack.com/create 에서 1분만에 생성 가능 (무료 플랜).

## §3. CI Workflow Rename (자율 실행 가능)

§1, §2 완료 후 — secret 3종 모두 GitHub 에 저장된 것을 확인한 다음:

```bash
cd /Users/seanbae/Desktop/취준/pivoxquant
for f in api-health daily-api-smoke post-deploy-canary daily-legal-scan weekly-security-scan morning-brief agent-health-weekly agent-upgrades-monthly weekly-memo-mon-0900-kst; do
  if [ -f ".github/workflows/${f}.yml.disabled" ]; then
    git mv ".github/workflows/${f}.yml.disabled" ".github/workflows/${f}.yml"
    echo "✅ enabled: ${f}.yml"
  else
    echo "⚠️ skip (not found): ${f}.yml.disabled"
  fi
done
git status
git commit -m "ci: enable 9 secret-gated workflows (RAILWAY_BACKEND_URL + SLACK_WEBHOOK_URL set)"
git push
```

## §4. 활성화 후 검증

1. **GitHub Actions tab** (저장소 상단 Actions) 열기
2. 좌측 workflow 목록에서 9건 각각 클릭 → 첫 실행 결과 확인
   - cron 기반: 다음 cron tick 까지 대기 (또는 **Run workflow** 수동 트리거)
   - push trigger: 위 commit 으로 이미 실행됨
3. **실패 시 즉시 revert**:
   ```bash
   cd /Users/seanbae/Desktop/취준/pivoxquant
   git mv .github/workflows/<failing-workflow>.yml .github/workflows/<failing-workflow>.yml.disabled
   git commit -m "ci: re-disable <failing-workflow> (BLOCKED: <reason>)"
   git push
   ```
4. **Slack 채널 검증**: 알림이 실제로 도착하는지 첫 1주일 모니터링

## 부록 — Secret 등록 후 확인 명령

GitHub CLI (`gh`) 가 설치되어 있다면 (자율 검증 가능):

```bash
gh secret list -R seanbae-analyst/pivoxquant
# expected output:
# RAILWAY_BACKEND_URL          Updated YYYY-MM-DD
# SLACK_WEBHOOK_URL            Updated YYYY-MM-DD
# WEEKLY_MEMO_TRIGGER_SECRET   Updated YYYY-MM-DD
```

> secret 값 자체는 GitHub UI/CLI 모두 reveal 불가 (write-only). 갱신 필요 시 `gh secret set <NAME> -R seanbae-analyst/pivoxquant`.
