## 1. Problem Statement

### Who (타겟 유저)
| Segment | 비중 | 특징 |
|---|---|---|
| 초보 투자자 | 60% | 매일 시장을 보기 부담, 뭘 봐야 할지 모름 |
| 중급 투자자 | 30% | 출근길 1분 안에 포트폴리오 훑고 싶음 |
| 파워 유저 | 10% | 실적발표/지표 캘린더 직접 관리 귀찮음 |

### What (겪는 문제)
> "매일 아침 증권사 앱 + 네이버 뉴스 + 경제 유튜브 3개를 30분씩 순회하는데, 결국 **내가 가진 종목이 오늘 뭐가 있는지**는 알 수 없다."

구체적 pain point 4가지:
1. **정보 과잉**: 시장 뉴스 100개 중 내 종목 연결된 건 2-3개인데 스크롤해야 찾음
2. **일정 파편화**: 실적발표/FOMC/CPI 일정은 따로 외우거나 구글 캘린더에 수동 입력
3. **무료함**: 앱을 매일 열 "이유"가 없음 — 거래 있는 날만 접속
4. **불안감**: 자는 동안 미장 무슨 일 있었는지 모른 채 출근하는 공허함

### Why now
- **경쟁**: 토스/카뱅은 "전체 인기 종목" 푸시, 증권사는 "가격 알림"뿐 — 개인화 브리핑 제로
- **비용**: Claude Haiku 등장으로 유저당 월 $0.03에 1줄 인사이트 생성 가능
- **기반**: PivoxQuant은 이미 포트폴리오 + 워치리스트 + 시장 캐시 보유 → 데이터 문제 없음

### Evidence
- blue-ocean-features.md 점수표: 가치 5/5, Pro 전환 5/5, 안전 5/5
- 업계 레퍼런스: Robinhood Snacks (일 300만 구독), Morning Brew (400만 구독) — "아침 브리핑" 포맷은 검증됨
- 국내 부재: 카뱅/토스/증권사 중 **개인 포트폴리오 기반** 브리핑 서비스 0개

## 2. Solution

### 2.1 Core
**"1분 안에 읽히는 4섹션 고정 포맷 + 1줄 AI 인사이트"**

```
┌────────────────────────────────────┐
│ GOOD MORNING, 상현님 — 4/15 (화) │
├────────────────────────────────────┤
│ 1. 어젯밤 미장 마감              │
│    S&P 500 +0.4% / NASDAQ +0.7% │
│    다우 -0.1%                   │
│                                  │
│ 2. 내 포트폴리오 (-0.2%, -42k) │
│    ▲ NVDA +2.1%  최고           │
│    ▼ TSLA -3.4%  최저           │
│                                  │
│ 3. 오늘 일정                    │
│    - AAPL 실적발표 (장마감후)  │
│    - CPI 지표 (21:30)           │
│                                  │
│ 4. 공포탐욕지수: 62 (어제 58)   │
│                                  │
│ 인사이트: 보유 종목 중 AAPL이  │
│ 오늘 실적발표 예정. 포트폴리오 │
│ 22% 비중.                       │
│                                  │
│ * 정보 제공 목적, 투자 판단은  │
│   본인 책임                     │
└────────────────────────────────────┘
```

### 2.2 UX Flow

**최초 설정 (온보딩, 3스텝)**:
1. 설정 → 아침 브리핑 켜기
2. 발송 시간 선택 (기본 06:00 KST / 07:00 / 08:00 / 09:00)
3. 채널 선택 (푸시 / 이메일 / 카톡) — 티어별 제한

**일일 경험**:
1. 06:00 — 푸시 도착: "상현님, 오늘 내 종목 2개 일정 있음"
2. 탭하면 → 홈 카드 자동 확장
3. "자세히 보기" → 각 섹션 원본 데이터 (예: CPI 예상치, 실적 컨센서스)

**오프라인 경험**:
- 푸시 못 봐도 홈 최상단 카드로 온종일 표시 (다음날 06:00에 교체)
- 아카이브 페이지 (`/morning-brief`)에서 과거 30일 열람

### 2.3 Edge Cases

| 케이스 | 처리 |
|---|---|
| 포트폴리오 비어있음 | "포트폴리오 추가 후 이용 가능" + 워치리스트 기반 대체 |
| 주말/공휴일 | 토요일/일요일/한국 공휴일 발송 안 함, 월요일에 "주말간 요약" |
| 시장 데이터 API 실패 | 가능한 섹션만 표시 + "일부 데이터 일시 불가" 배너 |
| Claude Haiku 응답 실패 | 인사이트 섹션 제외, 다른 섹션만 발송 |
| 신규 유저 (D+0) | 가입 후 최소 1일 지나야 발송 (데이터 축적) |
| 티어 강등 (Pro→Free) | 푸시/이메일 자동 off, 인앱 카드만 유지, 안내 메시지 |
| 발송 시간대 변경 | 다음날 06:00부터 적용 (당일은 기존 시간) |
| 시간대 겹침 (06:00 KST = 17:00 EDT) | KST 기준 하루 마감 후 생성 (미장 마감 = 06:00 이전) |

### 2.4 "뭘 안 넣나" (의도적 제외)

| 제외 | 이유 |
|---|---|
| 개별 종목 차트 이미지 | 텍스트 1분 읽기 컨셉 저해, 용량 증가 |
| "오늘 추천 종목" | **자본시장법 투자자문업 저촉** — 절대 금지 |
| 뉴스 본문 스크랩 | 저작권 위반 위험, 제목 + 출처 링크만 |
| 커뮤니티 반응 | v1 범위 초과, v2 검토 |
| 음성 브리핑 (TTS) | 개발 비용 대비 수요 불명확, v2 검토 |
| 실시간 가격 업데이트 | "아침 1회 스냅샷"이 컨셉 — 실시간은 기존 포트폴리오 페이지 |

## 3. Acceptance Criteria

### AC1. 생성
- [ ] Given 포트폴리오 ≥ 1종목 보유 When 매일 06:00 KST Then 해당 유저의 브리핑이 DB에 저장된다
- [ ] Given 브리핑 생성 When Claude Haiku 호출 Then 응답 시간 p95 < 3초, 실패 시 인사이트 제외하고 나머지 발송
- [ ] Given 주말/한국 공휴일 When 06:00 도달 Then 브리핑 생성 스킵

### AC2. 콘텐츠
- [ ] 브리핑은 4섹션 고정 + 인사이트 1줄 + 면책 1줄로 구성된다
- [ ] "추천", "매수", "매도", "~ 해야 한다" 단어가 포함되지 않는다 (validator 통과)
- [ ] 포트폴리오 섹션은 보유 종목 중 최대 3개만 (상승 1, 하락 1, 비중 최대 1)
- [ ] 일정 섹션은 내 종목 + 워치리스트와 매칭되는 이벤트만
- [ ] 전체 본문 ≤ 500자 (모바일 1분 읽기 기준)

### AC3. 발송
- [ ] Free 유저는 인앱 카드만 받는다 (푸시 X)
- [ ] Pro 유저는 푸시 + 이메일을 받는다
- [ ] Premium 유저는 카톡 알림톡을 추가로 받는다
- [ ] 유저가 설정한 시간대에 ±5분 이내 발송된다
- [ ] 푸시 제목은 50자 이내, 본문 발췌 120자 이내

### AC4. UI
- [ ] 홈 대시보드 최상단에 카드가 표시된다
- [ ] `/morning-brief` 라우트에서 최근 30일 아카이브 열람 가능
- [ ] 설정 페이지에서 시간/채널 변경 즉시 반영된다 (다음날부터)
- [ ] 카드는 접힘 상태(요약 1줄) ↔ 펼침 상태(전체) 전환 가능

### AC5. 법적
- [ ] 모든 발송물에 "정보 제공 목적, 투자 판단은 본인 책임" 면책 포함
- [ ] Claude 프롬프트에 "추천 단어 금지" 제약 명시
- [ ] 발송 전 regex validator로 금지어 체크 → 걸리면 인사이트 제외

## 4. 브리핑 콘텐츠 구성 (상세)

### 섹션 1. 어젯밤 미장 마감 (고정)
- S&P 500 / NASDAQ / 다우 / KOSPI (전일 대비 %)
- 원-달러 환율 (전일 대비 원)
- 데이터 소스: 기존 시장 캐시 (`market_snapshot` 테이블)

### 섹션 2. 내 포트폴리오 (동적)
- 전일 대비 총평가액 변동 (금액 + %)
- Top 3 중 **상승 1개**, **하락 1개**, **비중 최대 1개** (중복 시 병합)
- 수치는 **소수점 1자리**, 색상: 상승 #16A34A / 하락 #DC2626

### 섹션 3. 오늘 일정 (동적)
**대상 이벤트**:
- 실적 발표 (earnings) — 내 종목 + 워치리스트
- 경제 지표 (CPI, FOMC, 고용, GDP 등 — KST 시간 표시)
- 배당 기준일 (ex-dividend date)
- 무상증자/유상증자/액면분할 공시

**출처**:
- 실적: Finnhub earnings calendar API (기존 연동)
- 지표: 투자지표 캐시 (수동 등록 — 월 1회 어드민이 입력)
- 공시: DART Open API (기존 연동)

**표시 규칙**:
- 최대 3개, 우선순위: 내 종목 실적 > 경제지표 > 워치리스트 실적
- 없으면 "오늘 주요 일정 없음"

### 섹션 4. 심리 지표 (고정)
- VIX 현재값 + 전일 대비
- CNN Fear & Greed Index 현재값 + 분류 (Extreme Fear/Fear/Neutral/Greed/Extreme Greed)
- 1개 이상 API 실패 시 성공한 것만

### 섹션 5. 1줄 인사이트 (AI 생성)
- **Claude Haiku 호출**, max_tokens 80
- 입력: 섹션 1-4 데이터 요약 (JSON, 200 토큰)
- 출력 규칙:
  - 한 문장 (80자 이내)
  - 금지어 필터 통과 필수
  - 사실 기반 관찰만 ("NVDA가 비중 상위이며 오늘 엔비디아 컨퍼런스 일정이 있습니다")
  - 의견/추천 금지 ("NVDA 사세요" ❌)

### 섹션 6. 면책 (고정)
> "본 브리핑은 정보 제공 목적이며, 투자 결정과 책임은 본인에게 있습니다."

## 6. 개인화 깊이

| 레벨 | 입력 | 반영 |
|---|---|---|
| L1 (기본) | 보유 종목 | 포트폴리오 섹션, 실적 일정 매칭 |
| L2 | + 워치리스트 | 일정 섹션 확장 |
| L3 | + 관심 섹터 태그 | 인사이트에 섹터 관점 반영 |
| L4 | + 발송 시간대 | 06/07/08/09 KST 중 선택 (Premium만 커스텀) |
| L5 (v2) | + 보유 기간 | "장기 투자자 관점" 인사이트 톤 조정 |

v1 스프린트는 L1-L4까지 구현.

## 7. 합법성 (Critical)

### 자본시장법
- **투자자문업 미등록 상태** → 개별 종목 추천 절대 금지
- 금지 단어 regex: `(추천|사세요|매수|매도|살 만|팔 만|비중 확대|비중 축소)`
- 허용 표현: "오늘 일정이 있는 종목", "비중 상위 종목", "변동이 큰 종목"

### 저작권
- 뉴스 제목 표시 시 **출처 명시 + 원문 링크**, 본문 스크랩 금지
- 시장 데이터는 API 약관상 개인 유저 표시 허용 범위 내만

### 개인정보
- 이메일 발송 시 **수신 거부 링크** 필수 (정보통신망법)
- 카톡 알림톡은 광고성 아닌 **정보성 메시지**로 등록 (야간 발송 가능)
- 발송 로그는 90일 후 자동 삭제

### 면책 위치
- 인앱 카드: 하단 회색 1줄
- 이메일: 본문 최하단 + 구독 해지 링크
- 카톡: 본문 마지막 줄
- 푸시: 미포함 (글자수 제한, 인앱 진입 시 노출되므로 OK)

## 10. 기술 스펙

### 10.1 백엔드 구조
```
/services/morning_brief_service.py
  ├─ class MorningBriefGenerator
  │   ├─ collect_market_data()       # 섹션 1, 4
  │   ├─ collect_portfolio_delta()   # 섹션 2
  │   ├─ collect_today_events()      # 섹션 3
  │   ├─ generate_insight()          # 섹션 5 (Claude Haiku)
  │   ├─ validate_content()          # 금지어 체크
  │   └─ assemble()                  # 최종 조립
  └─ class BriefDispatcher
      ├─ dispatch_push()
      ├─ dispatch_email()
      ├─ dispatch_kakao()            # v1은 stub
      └─ save_archive()
```

### 10.2 Cron Job
- 스케줄러: **Vercel Cron** (기존 `/api/cron/*` 재활용)
- 엔드포인트: `POST /api/cron/morning-brief`
- 스케줄: `0 21 * * 0-4` (UTC 21:00 = KST 06:00 월-금)
- 타임아웃: 300초, 실패 시 Sentry 알림
- 배치 처리: 1000 유저씩 chunk, 병렬 5개 워커

### 10.3 DB 스키마
```sql
CREATE TABLE morning_brief (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id        UUID NOT NULL REFERENCES users(id),
  sent_date      DATE NOT NULL,           -- KST 기준 발송일
  content_json   JSONB NOT NULL,          -- 섹션별 구조화 데이터
  insight_text   TEXT,
  channels_sent  TEXT[] NOT NULL,         -- ['inapp','push','email']
  status         TEXT NOT NULL,           -- 'generated','sent','failed'
  error_log      TEXT,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (user_id, sent_date)
);
CREATE INDEX idx_mb_user_date ON morning_brief(user_id, sent_date DESC);

CREATE TABLE morning_brief_settings (
  user_id        UUID PRIMARY KEY REFERENCES users(id),
  enabled        BOOLEAN NOT NULL DEFAULT TRUE,
  send_time      TIME NOT NULL DEFAULT '06:00',
  channels       TEXT[] NOT NULL DEFAULT ARRAY['inapp'],
  include_watchlist  BOOLEAN NOT NULL DEFAULT TRUE,
  include_sectors    BOOLEAN NOT NULL DEFAULT FALSE,
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 15. User Stories

### 초보 투자자 (민지, 24세, 대학생)
> "나는 하루 1분만 투자 정보를 받고 싶은 초보로서, 매일 아침 출근길에 **내가 가진 종목 요약과 오늘 무슨 일이 있는지** 알고 싶다. 왜냐하면 증권사 앱은 정보가 너무 많고 무서워서 안 열게 되기 때문이다."

### 중급 투자자 (준호, 31세, 직장인)
> "나는 이미 5-10종목을 관리하는 중급자로서, **내 포트폴리오 변동을 일괄 요약**받고 오늘 **실적 발표나 경제지표가 있는지** 미리 알고 싶다. 왜냐하면 매일 종목마다 일정을 체크하는 게 번거롭기 때문이다."

### 파워 유저 (혜린, 38세, 풀타임 트레이더)
> "나는 하루 종일 시장을 보는 파워 유저로서, 아침 **06:00 기상 직후 1분 안에 전날 미장 + 오늘 트리거 이벤트**를 확인하고 싶다. 왜냐하면 기존 캘린더 앱은 종목과 연결되지 않아 수동 매핑이 필요하기 때문이다."
