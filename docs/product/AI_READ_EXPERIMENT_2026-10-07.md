
**캡처 15장** — 증권사 로고·이름·색 없이 흔한 화면 꼴만 흉내 냈다.

| 보유가 있는 화면 (10) | 보유가 없는 화면 (5) |
|---|---|
| a01 밝은 카드 — **평균단가가 화면에 없음**(평가금액·손익·수량만) · a02 어두운 카드 · a03 2단 그리드(종목명/손익/수익률 ↔ 수량/매입가/현재가) · a04 키-값 블록 + 종목코드 · a05 해외, 평단 옆에 원화 환산 · a06 국내+해외 섞임 · a07/a08 종목 상세의 "내 주식"(국내/해외) · a09 마지막 카드가 화면 아래로 잘림 · a10 해외 어두운 카드 | b01 체결내역 · b02 주문 화면 · b03 관심종목 · b04 계좌 합계 · b05 시세 화면 |

**판독기**: 이 세션(Claude Code)이 띄운 **별도 서브에이전트**. 도구 사용 금지, 규칙 + 마스킹 텍스트만 받았다(정답 파일 접근 없음).
서비스용 API 호출·프롬프트·비용과는 다르다. a09 는 처음 렌더에서 잘림이 안 생겨(생성기 버그) 고친 뒤 **새 판독기**로 그 1장만 다시 읽혔다.
`reader_2026-10-07.json` 은 판독기 출력을 옮겨 적으며 `check`(검산 설명) 문장을 일부 줄였다 — 값·상태는 원문 그대로.

## 2. 마스킹 결과

| 항목 | 값 |
|---|---|
| 신원 줄 삭제 (`계좌·위탁·고객·님`) | 7줄 |
| 불필요 줄 삭제 (`예수금·주문가능·출금가능`) | 3줄 |
| 남은 계좌번호꼴 가림 (`[가림]`) | 5건 |
| **새어 나간 개인정보** (가상 이름 · 계좌번호의 4자리 이상 조각) | **0** |

- **두 겹이 필요했다.** a06 의 "통합계좌" 머리줄은 OCR 이 `£57 =}` 로 읽어 키워드 삭제를 빠져나갔고, 같은 줄의 계좌번호는 숫자꼴 가림이 잡았다.
- OCR 은 한글을 음절로 띄운다("주 문 가 능") — 키워드는 **공백을 지운 줄**에 맞춘다.
- 한계: 계좌번호 3가지 꼴·가상 이름만 쟀다. 실제 앱의 고객번호·전화번호·주소 같은 건 아직 안 넣었다.

## 3. 결과 — 40행 × 4칸, 같은 OCR 덤프

칸 상태: **자동**(확신하고 맞음) · **확인**(추정으로 표시, 맞음 — 유저가 "맞아요") · **빈칸**(유저 입력) · **추정 틀림**(추정 표시라 유저가 고침) · **확신 틀림**(0 이어야 함).

| | 종목 | 수량 | 평균단가 | 통화 | 화면 판별 | 4칸 모두 맞게 채움 |
|---|---|---|---|---|---|---|
| **AI 판독** | 자동 30 · 확인 2 · 빈칸 3 · 추정 틀림 5 · **확신 틀림 0** | 30 · 7 · 3 · 0 · **0** | 31 · 9 · 0 · 0 · **0** | 31 · 9 · 0 · 0 · **0** | **15/15** | **29/40 행** |
| 지금 규칙 파서 | 자동 11 · 빈칸 29 · **확신 틀림 0** | 19 · 21 · **0** | 21 · 19 · **0** | 15 · 25 · **0** | 12/15 | 9/40 행 |

- 규칙 파서의 종목 칸은 서버 해석 규칙(마스터 코드, 아니면 정확한 이름)을 그대로 적용해 셌다.
- 규칙 파서는 a01·a05 를 잔고 화면으로 못 알아봤고 a10 을 체결 화면으로 봤다. 정답에 없는 행 20개(대부분 종목·숫자가 빈 자리표시 행이나 "수익" 같은 잡음 줄)를 남겼다 — 저장 전에 유저가 지워야 하는 행이다.
- **AI 는 보유 없는 화면 5장에서 행을 하나도 만들지 않았고**, 잘린 종목(a09 NHN)에 숫자를 넣지 않았다(OCR 잡음 `HO 120` 을 120주로 읽지 않음 — 정답은 130주).
- AI 가 해낸 것: 평균단가 없는 a01 에서 (평가금액−손익)÷수량으로 5종목 평단 유도(나누어떨어짐 + 손익률로 확인) · `219%`→219주, `1093`→109주 같은 단위 오독 복원(매입금액·평가금액 검산이 맞을 때만) · 상세 화면에서 수량이 `oF` 로 깨지자 투자원금÷평단=75 로 유도 · 원화 환산 평단을 USD 평단으로 쓰지 않음.

### AI 의 종목 "추정 틀림" 5건 — 모두 `guessed` 로 표시돼 유저 확인으로 간다

| 정답 | AI | 원인 |
|---|---|---|
| DL이앤씨 | 미이앤씨 | OCR `미 이 앤 씨`, 보정 못 함 |
| IPARK현대산업개발 | HDC현대산업개발 | **같은 회사의 옛 이름** — 서버 별칭 표가 있으면 맞는다 |
| ESR켄달스퀘어리츠 | 켄달스퀘어리츠 | OCR 이 `ESR`→`658`, 앞 잡음으로 버림 |
| SK텔레콤 | 텔레콤 | OCR 이 `SK` 를 놓침. 판독기가 "후보 여럿"이라 적음 |
| 지역난방공사 | 한국지역난방공사 | 화면 그대로가 맞았는데 **"정식명"으로 고쳐서 틀림** → 규칙 수정(§4-2) |

빈칸 3건(`= AREA`, `HZ ZY`, `NAA IB] AN`)은 OCR 이 종목명을 통째로 깨뜨린 경우 — 숫자는 다 맞게 채웠고 종목만 유저 입력.

### 이 결과를 믿기 전에

- **합성 15장 · 40행뿐이다.** 렌더러 하나(헤드리스 Chromium + WenQuanYi 폰트)라 레이아웃·폰트 다양성이 좁다. **실기기 캡처로는 안 쟀다.**
- 판독기는 서비스 API 가 아니다. 같은 규칙을 API 로 돌렸을 때의 정확도·지연·비용은 따로 재야 한다.
- 규칙 작성자는 a03 이미지 1장을 렌더 확인용으로 봤다(판독은 다른 에이전트가 했다).

## 4. 판독 규칙 (실험에 쓴 프롬프트 + 결과로 고칠 점)

### 4-1. 화면은 정하지 않는다 — **필수 칸이 보이는 화면이면 받는다**
유저에게 "이 페이지를 찍으세요"라고 강요할 필요가 없다. 대신 판독기가 화면 종류를 먼저 가르고, 필수 칸이 없는 화면은 **이유와 함께 돌려보낸다.**

| 화면 | 받나 | 돌려보낼 때 안내 |
|---|---|---|
| 잔고·보유 목록, 종목 상세의 "내 주식" | ✅ | — |
| 체결·거래내역 | ❌ (체결 가져오기 쪽으로) | "체결가·체결수량은 보유가 아니에요 — 잔고 화면을 올려 주세요" |
| 주문 화면 | ❌ | "주문 수량은 보유 수량이 아니에요" |
| 관심종목 · 시세 화면 | ❌ | "보유 정보가 없어요 — 잔고나 '내 주식' 화면을 올려 주세요" |
| 계좌 합계만 | ❌ | "종목별 목록이 보이는 화면을 올려 주세요" |

### 4-2. 꼭 읽혀야 하는 칸 — 하나라도 비면 그 행은 "유저 입력 필요"
1. **종목** — 이름 또는 코드/티커. **화면 표기가 그대로 읽히면 고치지 않는다**(정식명 변환은 서버 마스터가 한다 — §3 "지역난방공사" 교훈). OCR 이 깨진 것만 보정하고 `guessed`.
2. **보유수량** — 라벨(보유수량·보유·잔고수량) 또는 `N주`.
3. **평균단가** — 라벨(평균·평단·매입가·매입단가·1주 평균금액) 또는 유도: 매입금액(투자원금)÷수량, (평가금액−평가손익)÷수량 — **나누어떨어질 때만**.
4. **통화** — `$`→USD, `원`/`₩`→KRW. 깨졌으면 같은 행 다른 금액 표기로, `guessed`.

### 4-3. 검산 — 관계가 하나라도 보이면 반드시 맞춘다
수량×평단 ≈ 매입금액 · ≈ 평가금액−평가손익 · (현재가−평단)×수량 ≈ 평가손익 · 수량×현재가 ≈ 평가금액.
맞으면 verified. 관계가 있는데 안 맞으면 **숫자 칸을 비운다**. 관계가 없으면(a06 처럼 수량·평단·금액만) verified=false 로 유저 확인.
단위 오독 복원(`%`·`&`·`2` 로 읽힌 `주`·`원`, 잘린 앞자리)은 **검산이 맞을 때만**.

### 4-4. 절대 금지
현재가·시가·체결가·주문가·52주가를 평단으로 · 주문/체결 수량을 보유수량으로 · 원화 환산 평단을 USD 평단으로 ·
화면에 없는 숫자 만들기 · 관심종목/시세 화면에서 행 만들기 · 잘린 종목에 숫자 넣기 · **해석·평가·권유 문장**(출력은 추출 JSON 뿐).

### 4-5. 서버가 다시 하는 것 (AI 를 믿지 않는다)
종목은 마스터로 다시 해석(별칭 표 필요 — IPARK/HDC 사례) · 검산 재계산 · 통화와 종목 시장 일치 · 저장 전 유저가 칸별 확인.
지금 `services/imports/holdings_import.py` 의 commit 검증(행 하나라도 틀리면 400, 동의 필수)을 그대로 쓴다.
