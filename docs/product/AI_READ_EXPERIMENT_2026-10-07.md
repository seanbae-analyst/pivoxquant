**판독기**: 이 세션(Claude Code)이 띄운 **별도 서브에이전트**. 도구 사용 금지, 규칙 + 마스킹 텍스트만 받았다(정답 파일 접근 없음).
서비스용 API 호출·프롬프트·비용과는 다르다. a09 는 처음 렌더에서 잘림이 안 생겨(생성기 버그) 고친 뒤 **새 판독기**로 그 1장만 다시 읽혔다.
`reader_2026-10-07.json` 은 판독기 출력을 옮겨 적으며 `check`(검산 설명) 문장을 일부 줄였다 — 값·상태는 원문 그대로.

## 4. 판독 규칙 (실험에 쓴 프롬프트 + 결과로 고칠 점)

### 4-1. 화면은 정하지 않는다 — **필수 칸이 보이는 화면이면 받는다**
유저에게 "이 페이지를 찍으세요"라고 강요할 필요가 없다. 대신 판독기가 화면 종류를 먼저 가르고, 필수 칸이 없는 화면은 **이유와 함께 돌려보낸다.**

| 화면 | 받나 | 돌려보낼 때 안내 |
|---|---|---|
| 잔고·보유 목록, 종목 상세의 "내 주식" | ✅ | — |
| 체결·거래내역 | ❌ (체결 가져오기 쪽으로) | "체결가·체결수량은 보유가 아니에요 — 잔고 화면을 올려 주세요" |
| 주문 화면 | ❌ | "주문 수량은 보유 수량이 아니에요" |
| 관심종목 · 시세 화면 | ❌ | "보유 정보가 없어요 — 잔고나 '내 주식' 화면을 올려 주세요" |
| 계좌 합계만 | ❌ | "종목별 목록이 보이는 화면을 올려 주세요" |

### 4-2. 꼭 읽혀야 하는 칸 — 하나라도 비면 그 행은 "유저 입력 필요"
1. **종목** — 이름 또는 코드/티커. **화면 표기가 그대로 읽히면 고치지 않는다**(정식명 변환은 서버 마스터가 한다 — §3 "지역난방공사" 교훈). OCR 이 깨진 것만 보정하고 `guessed`.
2. **보유수량** — 라벨(보유수량·보유·잔고수량) 또는 `N주`.
3. **평균단가** — 라벨(평균·평단·매입가·매입단가·1주 평균금액) 또는 유도: 매입금액(투자원금)÷수량, (평가금액−평가손익)÷수량 — **나누어떨어질 때만**.
4. **통화** — `$`→USD, `원`/`₩`→KRW. 깨졌으면 같은 행 다른 금액 표기로, `guessed`.

### 4-3. 검산 — 관계가 하나라도 보이면 반드시 맞춘다
수량×평단 ≈ 매입금액 · ≈ 평가금액−평가손익 · (현재가−평단)×수량 ≈ 평가손익 · 수량×현재가 ≈ 평가금액.
맞으면 verified. 관계가 있는데 안 맞으면 **숫자 칸을 비운다**. 관계가 없으면(a06 처럼 수량·평단·금액만) verified=false 로 유저 확인.
단위 오독 복원(`%`·`&`·`2` 로 읽힌 `주`·`원`, 잘린 앞자리)은 **검산이 맞을 때만**.

### 4-4. 절대 금지
현재가·시가·체결가·주문가·52주가를 평단으로 · 주문/체결 수량을 보유수량으로 · 원화 환산 평단을 USD 평단으로 ·
화면에 없는 숫자 만들기 · 관심종목/시세 화면에서 행 만들기 · 잘린 종목에 숫자 넣기 · **해석·평가·권유 문장**(출력은 추출 JSON 뿐).

### 4-5. 서버가 다시 하는 것 (AI 를 믿지 않는다)
종목은 마스터로 다시 해석(별칭 표 필요 — IPARK/HDC 사례) · 검산 재계산 · 통화와 종목 시장 일치 · 저장 전 유저가 칸별 확인.
지금 `services/imports/holdings_import.py` 의 commit 검증(행 하나라도 틀리면 400, 동의 필수)을 그대로 쓴다.

- **판독기: 화면 분류 8/8, 지어낸 행 0, 확신하고 채운 틀린 숫자 0.** 목업 숫자가 안 맞자 규칙(§4-3)대로 칸을 비웠다 — 실제 유저 캡처라면 숫자가 맞아서 채워질 자리다. 이 세트로는 **정확도가 아니라 안전장치**를 쟀다.
- **마스킹 구멍 발견 → 고침.** 처음엔 계좌번호 숫자만 가려서 **같은 줄의 이름이 3장에서 샜다**(`124-4567-8900-XX[종합_주식] 김미래` 꼴).
  → 계좌번호꼴이나 `[종합…]` 같은 계좌 종류 표시가 있는 **줄을 통째로 삭제**하도록 `ai-read-mask.mjs` 수정. 이후 누출 0(실제 8장 · 가상 15장 모두). 가상 세트는 `[가림]` 줄이 사라진 것 말고 판독기 입력이 같다.
- **기존 규칙 파서의 위험 발견(r2) → 수정함.** 2단 머리글 표에서 현재가를 평균단가로, 매도가능 수량을 보유수량으로 **확신 상태로** 채웠다.
  원인: 2단 머리글의 윗줄(보유수량 · 평균가 · 평가손익)만으로도 1단 표 머리글 조건을 채워 1단 경로를 탔고, 종목마다 아랫줄이 별도 행이 됐다.
  같은 문제의 거울상도 있었다 — **아랫줄**(보유수량 · 매입가 · 현재가)만 1단 머리글로 잡히면 윗줄의 평가손익이 평균단가가 된다(가상 a03).
  수정(`parse-holdings.ts` `parseHoldingsScreen`): 1단 머리글 바로 밑에 2단 머리글의 둘째 줄이 있으면, 또는 1단 머리글이 2단의 아랫줄이면서 매입금액·평가금액 열이 없어 검산이 안 되면 2단 경로로 읽는다.
  매입금액/평가금액이 있는 키움형은 1단 경로가 검산으로 맞게 읽어 왔으므로 그대로 둔다(그걸까지 옮기면 broker 평가에서 자동 채움이 떨어지고 틀린 칸이 1개 생겼다 — 실측 후 좁힘).
  2단 경로에서 종목명 열 아래 칸이 숫자 필드(보유수량)면 아랫줄 숫자를 읽는다(6자리 종목코드는 제외).
  회귀 테스트 `frontend/src/lib/fill-ocr/__tests__/stacked-header-holdings.test.ts` (r2 형태 합성 + a03 덤프). 기존 평가(holdings · toss · broker · fills, Chromium/Safari) 출력은 수정 전과 **한 줄도 다르지 않다**.
  수정 후 r2: 6행, 수량은 보유수량 줄·평단은 평균가 줄에서(화면에 찍힌 값 그대로). 종목명 4개는 아랫줄 잡음 글자(`d`)가 잡혀 유저 입력으로 남는다.

**서버(`services/ai_read.py`)가 모델을 믿지 않는 장치**:
- 받은 텍스트를 한 번 더 마스킹(기기와 같은 규칙, 파이썬 사본 — `tests/test_ai_read.py` 가 같은 줄 모양으로 두 쪽을 맞춘다).
- 모델이 "읽었다"는 숫자는 **보낸 텍스트에 그대로 찍혀 있어야** 칸을 채운다. 아니면 힌트로만.
- 매입금액 · 평가금액−평가손익 · (현재가−평단)×수량 · 체결금액 관계를 **서버가 다시 계산**. 찍힌 관계가 안 맞으면 수량·단가를 비운다. 관계로 증명된 칸만 채우고 나머지는 힌트(유저 확인).
- 보유 화면이 아닌 판정이면 모델이 행을 줘도 버린다. 잘린 행은 숫자 없음.
- 텍스트·결과를 저장·로그하지 않는다(테스트로 고정). 응답은 `legal_scrub_response` 통과 — 매수/매도는 `action`(buy/sell) 키로만 나간다.
- 모델 `claude-opus-5-5`, structured outputs(JSON 스키마), effort medium, 거절 시 서버측 fallback(`fallbacks: "default"`), 거절·과다 입력은 422.
- 레이트리밋: 유저별 5/분 · 30/일(`security.ai_read_rate_limit`) — 일일 비용 상한.
