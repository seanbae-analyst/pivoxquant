# 체결 화면 캡처 → Import Inbox (Screenshot Import) — 설계

**작성일**: 2026-09-27 · 이웃 설계: [IMPORT_INBOX_DESIGN.md](IMPORT_INBOX_DESIGN.md)
**범위**: 증권사 앱 **체결/거래내역 화면** 캡처 → 체결 행 → 기존 `pending_trades` 흐름.
보유종목 화면 → 보유 맞추기(reconcile)는 범위 밖(§9).

## 0. 결정 이력

1. 처음엔 Claude vision 으로 설계·구현했다(국외이전 동의·플래그 포함).
2. **2026-09-27 방향 변경(사용자 확정): AI API 를 쓰지 않는다.** OCR + 규칙, 판별 못 한 칸은 유저가 직접 채운다.
   → vision 코드·국외이전 동의·업스트림 에러 코드는 이 PR 에서 모두 제거했다. `anthropic` 의존성 변화 없음.
3. OCR 엔진은 **브라우저 Tesseract.js** 로 정했다(§4 근거). 그래서 `IMPORT_INBOX_DESIGN.md` §원칙 1
   *"서버는 이미지·AI를 쓰지 않는다"* 가 그대로 지켜진다 — 이미지는 기기를 떠나지 않는다.

## 1. 흐름

```
/journal/import [캡처 이미지] 탭
  → 캡처 선택(여러 장 가능) → [읽기]
     브라우저: Tesseract.js (kor+eng) 로 단어+좌표 → 숫자 칸은 숫자 전용으로 한 번 더 읽기
             → 규칙 파서(lib/fill-ocr/parse.ts): 화면 판별 → 행 묶기 → 칸 채우기(증명된 것만)
  → 검토 표: 증명 못 한 칸은 빈칸 + 테두리 강조 + OCR 읽은 값은 placeholder 힌트로만
     유저가 빈칸을 모두 채워야 [대기함에 올리기] 활성
  → POST /api/portfolio/imports/image  JSON {consent, broker, rows[]}   ← 이미지 없음
     서버: 재검증(클라이언트 불신) → RawTrade → _ingest → pending_trades (중복 제거·멈춤 매칭 그대로)
  → /journal ImportInbox 에서 thesis + 승인 → ledger (기존 그대로)
```

**자동 반영 없음. 추측으로 채우지 않음.** 유저가 확인한 행만 대기함에 들어가고, 승인은 기존처럼 행마다.

## 2. 캡처 기준 (업로드 화면 안내와 같은 내용)

- **화면**: 체결내역 / 거래내역. 보유종목(잔고)·미체결 주문·기타 화면은 이름을 대고 읽지 않는다.
  증권사별 메뉴 경로는 **실기기로 확인하지 않아 적지 않았다** (TODO: 실기기 캡처로 확인 후 추가).
- **꼭 보여야 하는 칸**: 체결일(가능하면 시각) · 종목명 또는 코드 · 매수/매도 **글자** · 체결수량 · 체결단가.
  **있으면 좋은 칸**: 통화 · 체결금액(보이면 수량×단가 대조).
- **좋은 캡처**: 화면 전체, 원본 해상도, 날짜 머리글/조회 기간이 보임. **나쁜 캡처**: 잘린 행·확대·흐림·가로 잘림·메신저 재압축본.
- **최소 해상도: 짧은 변 ≥ 320px, 긴 변 ≥ 480px** (`ocr.ts` `MIN_SHORT_EDGE`/`MIN_LONG_EDGE`). 미달이면 OCR 전에 거절.
  근거: 폰 원본 캡처는 짧은 변 ≥ 640px, 이보다 작으면 썸네일·재압축본. 합성 312×675(`h`)가 여기서 거절된다(의도).
- 장당 10MB 이하, PNG/JPEG/WEBP. 여러 장 → 한 OCR 세션에서 순차 처리, 겹친 행은 서버 dedupe 가 `duplicate`.
- 증권사 선택(모름·기타 포함)은 배치 라벨(`broker_guess`)일 뿐 파싱은 같다.

## 3. 읽는 규칙 (`frontend/src/lib/fill-ocr/parse.ts`, 순수 함수)

원칙: **칸은 화면이 증명할 때만 채운다.** 아니면 `value: null` + 힌트.

| 칸 | 채우는 조건 |
|---|---|
| 숫자(수량·단가·금액) | 페이지 OCR 과 숫자 전용 재판독이 **같은 숫자**일 때. 천 단위 쉼표가 어긋나면(`1448,000`) 불인정. 둘이 다르면 후보 조합 중 `수량×단가≈금액`(±0.5%)을 만족하는 조합이 **정확히 하나**일 때만 채택 |
| 수량(추가) | 뒤에 별도 `주` 토큰이 있을 때만. 없으면 금액 대조로 확인될 때만 — `12.5주`의 `주`가 숫자로 삼켜져 `12.53`이 되는 사례(실측) 때문 |
| 금액 불일치 | 모든 칸이 증명됐는데 `수량×단가≠금액` → 셋 다 비우고 `amount_mismatch` 표시(화면 자체가 틀린 경우 유저 판단) |
| 매수/매도 | 글자(매수·매도·구매·판매·Buy·Sell)만. 둘 다 있거나 없으면 판별불가. **색만 있는 라벨은 읽지 않는다** |
| 날짜 | 행에 찍힌 날짜, 또는 위의 날짜 머리글(`9월 23일`은 화면의 연도(`2026년`, 조회 기간)가 있을 때만) |
| 시각 | `HH:MM(:SS)`, 두 판독의 숫자가 같을 때. **ET(미국 동부) 표시면 시각은 버리고 날짜만** — DST 오프셋을 추측하지 않는다 |
| 종목 코드 | 6자리 코드는 **이름 줄에서만**(가격 `201000`이 코드로 둔갑한 사례 실측). US 티커는 **$금액이 있는 줄에서만**(펀드 설명 속 `TSLA`를 `TSLL`로 착각한 사례 실측) |
| 종목명 | OCR 글자 그대로 **라벨로만** 보낸다. 확정은 서버: 코드 → 정확한 마스터 이름 → 퍼지(§5, 확인 필요) → 실패 시 `needs_ticker` |

화면 판별: 체결 키워드(체결내역·체결단가·구매완료…) + 체결 모양 줄(`체결 10주`, `10주 구매`, `N x $P`) vs 보유 키워드
(보유종목·평가금액·평균…; 하단 탭 라벨인 `잔고`·`현재가`는 제외) vs 주문 키워드(지정가·주문유형·정정…).
레이아웃: 표 머리글(체결일자·종목명·구분·수량·단가·금액·수수료…) 3개 이상이면 **표 모드**(열 x좌표로 배정, 합계 줄 제외, 여러 줄 셀 병합),
아니면 **카드 모드**(수량 줄을 기준으로 가까운 이름 줄·시각 줄을 묶음, 날짜 머리글을 넘지 않음).
제외: `미체결`/`체결 0주` → 미체결, `취소`/`정정` → 취소, 화면 위·아래에서 잘린 카드 → 잘림.

## 4. OCR 엔진 선택 — 근거 (2026-09-27 실측)

| 후보 | 개인정보 | 정확도 | 운영 | 결정 |
|---|---|---|---|---|
| **(a) 브라우저 Tesseract.js kor+eng** | 이미지가 기기를 안 떠남 → 국외이전·보관 문제 없음 | §7 표(합성 12장) | 첫 사용 시 ≈8MB(언어 4.3MB+코어) 1회 다운로드, 캡처당 ≈3~8초(M 시리즈 맥 Chromium 실측) | **채택** |
| (b) 서버 PaddleOCR/EasyOCR | 이미지 서버 전송·보관 부담 | **측정 안 함** | Render free 512MB·torch/paddle 의존성 — 이미지 빌드 검증 불가(로컬 Docker 없음, CLAUDE.md 함정 5) | 보류 |
| (c) Claude vision | 국외이전(§28-8) | 측정 불가(크레딧 부족 400) | 호출당 ≈20~35원 | 사용자 결정으로 제외 |

(b)를 재지 않은 이유: (a)가 "틀리게 확신 0"을 만족했고, 남은 격차(판별불가 비율)는 유저 입력으로 메워지는 구조라 서버 이미지 전송의 비용을 정당화하지 못한다.
실기기 캡처에서 (a)의 판별불가 비율이 너무 높으면 그때 (b)를 같은 평가 세트로 잰다.

## 5. 서버 (`routes/imports.py` `POST /image`, `services/imports/ocr_rows.py`)

- 본문 `{consent:true, broker?, rows:[{date, time?, tz, name, code, action, shares, price, currency, source_text, user_filled[]}]}`.
  **multipart/이미지는 받지 않는다**(400). 행은 완성돼 있어야 한다 — 빈칸·형식 오류는 행 이름을 대고 400 `IMPORT_INVALID_FIELD`, 배치 0.
- 검증: 매수/매도, 수량·단가 `amount_ok`, 통화 KRW/USD, KRW 수량 정수, 날짜 `YYYY-MM-DD` 실제 날짜, 시각 `HH:MM[:SS]`,
  `tz != KST` 이면 시각 버림, 미래·1990 이전은 `_ingest` 가 skip. 최대 200행.
- 종목: `resolve_ticker`(코드 → 정확한 이름). 실패 시 **퍼지**: 한글 2자↑, `SequenceMatcher` ≥ 0.75, 2위와 차이 ≥ 0.1 일 때만 →
  confidence 0.6 + `raw_snippet` 에 `[확인: 종목 — 읽은 이름 'X' → Y]`. 그 외 `needs_ticker`.
- `raw_snippet` = 화면 원문 한 줄(`source_text`, 계좌번호 마스킹) + `[직접 입력: 단가·구분]`(유저가 채운 칸).
- 승인 게이트: `source=screenshot_image` 이고 confidence < 0.7(= 퍼지 종목) → 티커를 직접 고르거나(PATCH → 사용자 확인값)
  승인 시 `confirm_values:true` 없으면 400 `IMPORT_CONFIRM_REQUIRED`. 텍스트·CSV 행은 영향 없음.
- DTO 에 `source`·`needs_confirm` 추가(`PendingTrade.batch` viewonly joined 관계). **스키마 변경·마이그레이션 없음.**
- 시세 서비스는 부르지 않는다 — 체결가는 화면 값(유저 확인)만. 시세 지연·부재·휴장·벤더 표시 플래그와 무관.

## 6. 개인정보 · 보안

- 이미지는 브라우저 메모리에서만 처리, 서버·로그·DB 어디에도 없다. 국외이전 없음 → 별도 동의 불필요, 처리방침 변경 불필요.
  기존 수집·이용 동의 체크박스(가져오기 공통)만 받는다.
- CSP: Tesseract.js 런타임(worker·core·언어 데이터)을 `public/tesseract/`에 self-host(`scripts/copy-tesseract-assets.mjs`,
  predev/prebuild 에서 node_modules 복사, gitignore). `worker-src 'self'` 그대로, `script-src` 에 **`'wasm-unsafe-eval'`만 추가**
  (WebAssembly 컴파일만 허용, eval 아님). CDN·blob: 워커 없음. data: URI 로 wasm 을 끼워 넣은 `*.wasm.js` 빌드는
  `connect-src` 위반을 내므로 `.js`+`.wasm` 분리 빌드를 쓴다(실측).
- 추천·조언 문구 없음. 응답은 `legal_scrub_response`.

## 7. 정확도 — 합성 12장, 프로덕션 경로 그대로 (2026-09-27)

측정: `frontend/scripts/ocr-eval-dump.mjs` 가 **프로덕션 `ocr.ts`를 Vite 로 번들해 헤드리스 Chromium(Playwright)에서** 돌려
단어 덤프를 만들고(`tests/fixtures/screenshot_import/synthetic/ocr/`), `lib/fill-ocr/__tests__/eval.test.ts` 가 파서를 돌려 채점.
종목은 서버와 같은 기준(코드 또는 **정확한** 마스터 이름만 자동, 퍼지는 확인 필요 → 판별불가로 셈).

| 칸 | 자동 인식 | 판별불가(사용자 입력) | 틀리게 확신 | n |
|---|---|---|---|---|
| 날짜 | 81% | 19% | **0** | 54 |
| 시각 | 63% | 38% | **0** | 32 |
| 종목 | 52% | 48% | **0** | 54 |
| 매수/매도 | 39% | 61% | **0** | 54 |
| 수량 | 69% | 31% | **0** | 54 |
| 단가 | 74% | 26% | **0** | 54 |
| 금액 | 69% | 31% | **0** | 54 |
| 통화 | 83% | 17% | **0** | 54 |

화면 판별 12/12: `j`(보유)·`k`(주문)·`l`(채팅) 거절, `f` 잘린 행 제외, `g` 미체결·취소 제외, 없는 행 0.
`h`(312×675 흐림)는 최소 해상도로 거절 → 8행 전부 판별불가로 셈.
`eval.test.ts` 는 **틀리게 확신 > 0 이면 실패**한다(회귀 게이트).

**한계 — 반드시 같이 읽을 것**
- 규칙을 **이 12장을 보면서 조정했다.** 같은 세트의 점수는 낙관적이다. 실기기 캡처 평가 세트가 필요하다(`tests/fixtures/screenshot_import/README.md`).
- 매수/매도 자동 인식이 낮다(39%): 합성 화면 다수가 색 박스 라벨이라 글자가 안 읽힌다. 색으로 추측하지 않기로 했으니 이건 유저 입력으로 간다.
- 처음 `sharp` 전처리로 잰 수치(틀림 0, 자동 인식 더 높음)는 **브라우저 canvas 경로와 달랐다** — 브라우저에서 돌려 보니 US 화면 행 분리·
  `12.5주→12.53` 같은 오류가 나왔고, 그걸 고친 뒤 위 표를 다시 쟀다. 그래서 덤프는 이제 프로덕션 경로로만 만든다.
