## TL;DR (3줄 요약)

- 투자자는 "이 뉴스가 내 종목에 좋은 뉴스인가, 얼마나 심각한가, 지금 뭘 해야 하나"를 판단하지 못해서 뉴스 보고도 행동을 못 한다. 네이버/토스는 뉴스 "나열"만 해준다.
- PivoxQuant은 뉴스를 **수집 → 종목 매핑 → 임팩트 스코어(−5~+5) → AI 1줄 판단 → 내 포트폴리오 매칭**까지 한 흐름으로 처리하는 **유일한 서비스**가 된다.
- MVP는 **1주일 + 월 $25 API 비용** 안에 가능. Pro 9,900원 전환율 +2~3%p 기여가 목표. 실패 시그널은 월간 활성 뉴스 조회 세션 < 30%.

## 1. 제품 정의

### 1.1 Problem Statement (JTBD)

> **When** 내 종목에 관련된 뉴스 헤드라인이 뜨면
> **I want to** 이게 내 포지션에 얼마나 중요한지, 좋은 건지 나쁜 건지 3초 안에 알고
> **So I can** 매매/홀딩/손절을 즉시 결정할 수 있다.

**증거 (왜 지금 해야 하는가)**:
- 2024~2025 국장 개인투자자 이탈 주요 원인: "뉴스는 봤는데 해석을 못 해서 대응을 놓쳤다" (금투협 설문 인용 가능)
- 미장 Reddit/WSB에서 "Claude/ChatGPT에 뉴스 붙여넣고 해석 물어봄"이 신규 투자자 루틴화
- PivoxQuant 기존 유저 Feature Request Top 3 추정: 뉴스 요약 / 알림 / 포트폴리오 영향도
- 경쟁사 분석: 네이버 금융 = 나열, 토스증권 = 큐레이션 (해석 없음), 스탁플러스 = 제공 안 함

**Pain Points 우선순위**:
1. **정보 과다** — 하루 300개 뉴스 중 내 종목 관련 5개를 찾는 데 15분
2. **해석 부재** — "FOMC 0.25% 인상"이 내 삼전 포지션에 호재인가 악재인가?
3. **언어 장벽** — 미장 뉴스 영어 원문 → 개인투자자가 뉘앙스 파악 어려움
4. **타이밍 지연** — 뉴스 본 시점엔 이미 주가 반영됨 → 실시간 알림 필요

### 2.2 임팩트 스코어 정의

**스케일**: −5 (극단적 악재) ~ 0 (중립) ~ +5 (극단적 호재)

**계산 방식 (v1 — 룰 + LLM 하이브리드)**:

```
Step 1: Claude Haiku로 1차 sentiment + magnitude 분류
  Input: 뉴스 제목 + 본문 앞 500자 + 종목명/섹터
  Output: {sentiment: bull/bear/neutral, magnitude: 1-5, reason: "..."}

Step 2: 룰 기반 보정
  +/- 1: 어닝 서프라이즈, FDA 승인/거절, M&A 확정 → magnitude 최소 3
  +/- 2: FOMC/한은 금리 → 섹터 전체 적용
  −2: 횡령/회계부정/상폐 경고 → magnitude 5 강제
  0: "~할 예정", "검토 중" → magnitude 최대 2 (미확정)

Step 3: 최종 스코어 = sentiment_sign × magnitude
```

**표시 방식**:
- `+4` (진한 초록, 불꽃 아이콘): "대형 호재"
- `+2` (연초록): "호재"
- `0` (회색): "중립/정보성"
- `−2` (연빨강): "주의"
- `−4` (진빨강): "악재"

### 2.3 AI 요약 프롬프트 (Claude Haiku)

```
You are a Korean stock news analyst. Given a news article, output JSON:
{
  "tickers": ["AAPL", "005930"],
  "sentiment": "bullish" | "bearish" | "neutral",
  "magnitude": 1-5,
  "one_liner_ko": "30자 이내 한글 요약, 판단 포함",
  "reason": "왜 이 점수인지 1문장",
  "category": "earnings|macro|regulatory|M&A|product|other"
}

Rules:
- magnitude 5: 주가 ±5% 이상 이동 예상
- 투자 권유 금지 ("사세요", "파세요" X)
- "~할 수 있다", "주목됨" 같은 약한 표현
- 불확실하면 neutral 선택
```

**토큰 추정**: 입력 800 + 출력 150 = 950 tokens/건 × $0.25/1M = **$0.00024/건**

### 2.4 Phase 2 — 확장 (MVP 검증 후 2주)

- **실시간 알림**: magnitude ≥ 4 발생 시 푸시 (Premium only)
- **포트폴리오 자동 매칭**: 보유 종목 교집합 → "내 포트폴리오 영향도" 카드
- **섹터 영향도**: 예) "반도체 섹터 평균 −2" 요약
- **과거 반응 학습**: "유사 뉴스 발생 시 과거 30일 평균 수익률"
- **뉴스→자동매매 트리거**: magnitude ≤ −4 시 손절 자동 실행 (Premium, 옵션)

| 연합뉴스 경제 RSS | 무료 | 높음 | 제목/링크 | **MVP 채택** |

**법적 주의**:
- 네이버/다음 스크래핑은 **저작권법 + ToS 위반** → 배상현 1인 법인 리스크 큼. 절대 금지.
- RSS 피드는 **제목 + 링크 + 발행시간**만 저장, 본문은 원문 링크로 유도. "Fair use 미적용 상정"으로 보수적 운영.
- AI 요약은 "원문을 실질적으로 대체하지 않음"을 증명해야 함 → 요약은 **30자 1줄로 최소화** (판단만, 내용 재구성 X).

**MVP 국장 전략**:
1. DART 공시 (공공, 안전) — 주요 재무/경영 이벤트
2. 한경/연합 RSS 제목만 → AI로 종목+임팩트 분류 → 원문 링크
3. 본문이 필요하면 사용자가 클릭해서 외부 사이트에서 읽음 (저작권 우회)

## 4. AI 분석 파이프라인

### 4.1 아키텍처

```
┌─────────────┐   ┌──────────┐   ┌──────────────┐   ┌───────────┐   ┌──────┐

     ↑ cron 15분                                         ↑ 배치 (10건 묶음)
```

### 4.2 비용 추정 (월간)

**가정**:
- 뉴스 수집: 미장 200건/일 + 국장 100건/일 = **300건/일 = 9,000건/월**
- 종목 매핑 후 AI 분석 대상: 중복 제거 후 **60% = 5,400건/월**

| 항목 | 단가 | 월 비용 |
|---|---|---|
| FMP News API | $22 (기존) | $0 추가 |
| Claude Haiku (sentiment + 요약) | $0.00024 × 5,400 | **$1.30** |
| Claude Sonnet (복잡 케이스 10%) | $0.006 × 540 | **$3.24** |
| 캐시 (Redis/Upstash Free) | Free tier | $0 |
| DB 증가 (Supabase) | Free tier 내 | $0 |
| **합계** | | **≈ $5/월** |

실시간 푸시 알림 추가 시 (Phase 2): +$5 (FCM 무료 + 인프라)

**총합 월 $25 이하** — Pro 3명 추가 가입 시 손익분기.

### 4.3 캐싱 전략

- **종목 매핑**: 동일 제목 해시 → 7일 캐시 (같은 뉴스가 여러 소스로 재발행됨)
- **AI 분석 결과**: news_id 기준 영구 저장 (재분석 안 함)
- **프론트 응답**: 티커별 최근 뉴스 리스트 10분 캐시
- **Rate Limit**: 유저당 분당 20req (Free), 60req (Pro+)

### 7.2 DB 스키마

```sql
CREATE TABLE news (
  id SERIAL PRIMARY KEY,
  source VARCHAR(50),           -- 'fmp', 'dart', 'hankyung'
  external_id VARCHAR(200) UNIQUE,
  title TEXT NOT NULL,
  url TEXT,
  published_at TIMESTAMP,
  market VARCHAR(10),           -- 'US', 'KR'
  raw_content TEXT,             -- 본문 (RSS는 NULL)
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE news_impact (
  news_id INT REFERENCES news(id),
  ticker VARCHAR(20),
  sentiment VARCHAR(10),        -- 'bullish', 'bearish', 'neutral'
  magnitude SMALLINT,           -- 1-5
  score SMALLINT,               -- -5 ~ +5
  one_liner_ko TEXT,
  reason TEXT,
  category VARCHAR(20),
  ai_model VARCHAR(20),
  PRIMARY KEY (news_id, ticker)
);

CREATE INDEX idx_news_impact_ticker ON news_impact(ticker);
CREATE INDEX idx_news_published ON news(published_at DESC);
```

## 12. 비판적 검토: "이거 진짜 만들 가치 있나?"

**YES, 왜**:
1. **기존 인프라 재활용률 >90%** — FMP, Claude, DART 이미 연동. 순수 신규는 UI + 파이프라인 로직뿐.
2. **비용 $5/월** — 실패해도 손실 미미. Pro 1명이면 손익분기.
3. **차별화 명확** — 임팩트 스코어는 경쟁사에 없음. 6개월 선점 가능.
4. **기존 유저 유지율 레버리지** — "왜 PivoxQuant을 매일 열어야 하나?"에 답이 됨.
5. **Pro 전환 장치** — Free 한도 걸면 자연스러운 유료화 명분.

**NO, 왜 (반론)**:
1. **58개 퀀트 모델이 더 시급** — 기존 모델 완성도가 덜 함. 핵심 가치 제안 먼저 강화해야.
2. **뉴스 감성 정확도 낮음** — Claude도 60% 수준. 유저 신뢰 잃으면 전체 제품 신뢰도 훼손.
3. **법적 리스크** — 자문업 규제 회색지대. 1인 법인이 감당하기 어려움.
4. **경쟁 포화** — 뉴스 요약은 LLM 오면서 누구나 할 수 있는 영역으로 상품화됨.

**결론**:
> **조건부 GO**. 단, (a) 법률 자문 선행, (b) 퀀트 모델 완성도가 60% 이상일 때만 착수. 지금 (2026-04-14) 기준 퀀트 완성도가 낮다면 **뉴스 기능은 Phase 2로 연기**, 기존 모델 완성 + AI Assistant 강화에 먼저 투자. **단, 기본 수집 파이프라인 (Day 1~2)만 먼저 구축**해두고 데이터를 쌓으면서 Phase 2 착수 시 학습 데이터로 활용.
