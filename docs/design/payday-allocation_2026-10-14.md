## 무엇

월급날마다 들어온 돈(선택)을 생활비·저축·투자·기타로 어떻게 나눌지 적는다. 투자 몫은 그 월급 주기
(월급날 ~ 다음 월급날)에 유저 본인의 체결로 넣은 돈(산 금액 − 판 금액)과 나란히 보여 준다. 다음 월급날에는
나머지 몫이 어땠는지 "계획대로 / 덜 / 더" 로 스스로 적는다. 행동 근거: 미리 정해 두는 저축
(Thaler & Benartzi 2004, SMarT — 단 DOL CLEAR 는 인과 근거 "낮음" 판정).

## 왜 금액을 서버에 두지 않나 (CEO 2026-10-14 "변호사 자문 어려우니 최대한 안전하게, 법적 리스크 없이")

### 서버에 두면 생기는 쟁점 (agent 판단 — 법률 자문 아님)

legal-kr-fintech 에이전트 검토 + 직접 조사(2026-10-14) 결론: 서버 저장도 **조건부 가능, 위험도 중간**.

| 쟁점 | 근거 | 서버 저장 시 필요했던 것 |
|---|---|---|
| 소득 = 개인정보 (민감·고유식별 아님) | 개인정보 보호법 §23·시행령 §18·§19 | 처리방침 개정(동결 파일 `privacy-ko.md`) |
| 몫 금액은 §15①4 로 처리 가능하나, 선택 입력인 월급 총액은 "필요" 입증이 약함 | §15①4 (2023-09-15 시행, "불가피" 삭제) · §22③ 구분 공개·입증책임 | 월급 총액 별도 선택 동의(§15①1), 철회 시 총액만 파기 |
| 소득은 신용정보법상 "신용거래능력 판단 정보", 거래 기록과 결합 시 개인신용정보로 볼 여지 | 신용정보법 §2 1호 라목 가목("소득의 총액") · 금융위 법령해석 2023-04-03 · 대법원 2004도1639 | 신용정보제공·이용자 해당 여부 변호사 확인 |
| 월급날 푸시 정보성 여부 | 정통망법 §50 · KISA 안내서(2차) | 옵트인·기본 꺼짐·광고 혼입 금지 |

### 그래서: 받지 않는다

- **금액(월급·몫 4개·돌아보기)은 브라우저 `localStorage` 에만**, 키 `pq.payday.v1.u<userId>`. 어떤 API·URL·분석·로그에도 싣지 않는다.
- 카드가 하는 네트워크 요청은 **GET 2개뿐**: 본인 체결 `GET /api/portfolio/trades?limit=100` (이미 수집 중인 데이터), 환율 `GET /api/market/fx` (시세 표시 예외 — CLAUDE.md, 출처 표기는 `/portfolio` 하단 `FxAttribution`).
- 테스트로 고정: 실제 SWR 훅을 기록된 `fetch` 로 돌려 **모든 요청이 GET 이고 입력한 금액이 어떤 URL·본문에도 없음**을 확인. Playwright 실브라우저(데모 모드)에서도 비-GET API 요청 0건, 저장은 localStorage 키 하나.
- 근거:
  - 개인정보처리자 = "업무를 목적으로 개인정보파일을 운용하기 위하여 스스로 또는 다른 사람을 통하여 개인정보를 처리하는 자"(§2 5호), 처리 = 수집·저장 등. 운영자가 받지도 저장하지도 접근하지도 않으면 운영자의 처리로 보기 어렵다는 논리. **국내 공식 유권해석은 찾지 못했다**(직접 검색 2026-10-14).
  - 업계 기준: Apple App Privacy 의 "collect" = 기기 밖으로 전송되어 실시간 처리 이상 보관되는 것. 기기 안에서만 처리되는 데이터는 수집이 아니다.
  - 저장소 선례: 계좌 줄은 기기를 떠나지 않는 마스킹(`lib/fill-ocr/mask.ts`), "키는 서버에 오지 않는다"(`docs/launch/ACCOUNT_SYNC_STRATEGY_V2.md`).
- 그래서 처리방침 개정·별도 동의·파기 경로·내보내기 편입이 **필요 없다**. Sentry 는 분석 동의 시에만 켜지고 리플레이 0·`sendDefaultPii: false`, 카드는 금액을 로그로 남기지 않는다.

### 대가 (화면에 밝힘)

- 다른 기기에서 안 보이고, 브라우저 데이터를 지우면 사라진다. 시작 화면에 그대로 적고(이후엔 자물쇠 한 줄), "지우기"(이 기기에서 지우기) 버튼을 둔다.
- 회원 탈퇴 요청(유예·즉시 둘 다)이 성공하면 이 브라우저에 남은 **그 유저의** 배분도 지운다(`lib/api.ts` — `/api/auth/me` 로 확인된 유저만, 로그아웃은 유지). 처리방침 §8.5 에 기기 안 저장으로 적었다(2026-10-14).
- 서버가 금액을 모르므로 **월급날 푸시·"투자 몫 초과" 체결 푸시는 없다**. 월급날이 지나면 카드가 새 주기 입력칸으로 바뀌는 것이 리마인더다.
- 체결 목록은 최근 100건까지(라우트 상한). 그 안에 주기 시작 이후 체결이 꽉 차 있으면 "최근 100건까지만 셌어요" 표시.
- 체결 날짜는 API 의 UTC 날짜, 주기 경계는 KST 날짜 — 경계일 새벽 체결은 하루 어긋날 수 있다. 화면에 "대략값".
- 달러 체결은 오늘 환율로 환산(거래일 환율은 체결 행에 없다). 환율을 못 받으면 합계를 비우고 "환율을 불러오지 못했어요" — 추정하지 않는다.

## 화면 (CEO 2026-10-14 "너무 AI 같음" → 다시 그림)

글 대신 그림: 큰 금액(만원 단위, 딱 떨어지지 않으면 원 단위 그대로 — 같아 보이는 두 숫자는 실제로 같다) ·
몫 4칸을 한 막대에(2px 간격, 고정 순서, 미정 = 트랙) · 막대 아래 이름+금액 범례(색만으로 구분하지 않음) ·
투자 몫과 넣은 돈을 같은 눈금의 막대 두 개로. 주의 문구는 "계산 방법" 접기 안으로, 저장 안내는 자물쇠 한 줄.
색은 브랜드 중립색 4단(아이보리 70% · 브론즈 62% · 브론즈 · 아이보리 38%) — dataviz 검증 CVD ΔE 18.2, 대비 ≥ 3:1.

## 설계 제약 (법무 검토 반영)

1. 몫은 **고정 4칸, 금액만**. 자유 라벨·메모 없음 — "병원비"(건강)·"헌금"(신념) 같은 민감정보 우발 수집 방지.
2. **비율·틀(50/30/20)·기본 금액 없음.** "지난 배분 그대로"만. 문구: "서비스는 비율이나 금액을 권하지 않아요." 화면에 % 도 찍지 않는다.
3. **사후 사실만.** "몫보다 많음" 칩(브론즈, 경보색 아님) — 투자 몫보다 많이 넣었을 때만. 적게 넣은 건 표시하지 않는다(한 방향 원칙, `docs/design/my-rules_2026-10-14.md`). 멈춤(/pre-trade)에 "남은 투자 몫" 같은 사전 경고를 띄우지 않는다.
4. **거래 동사 없음.** "매수·매도·순매수" 대신 "산 금액·판 금액·넣은 돈". 추천·조언·권장·적정·목표·지키기 없음 (테스트로 고정).
5. 기능명 "월급날 배분" — "지키기" 같은 규범어 제외.
6. 또래 비교·제3자 제공·은행/카드 연동·자동 이체 없음.

## 서버로 옮기려면 (나중에)

월급날 푸시나 기기 간 동기화가 필요해지면 그때 서버 저장으로 옮긴다. 선행 조건:
- `privacy-ko.md` 개정(동결 파일 — legal-kr-fintech 승인) — 수집 항목·목적·§22③ 근거 구분·보유·변경 이력. 초안은 아래 에이전트 보고서 §5.
- 월급 총액은 기능 진입 시점 별도 선택 동의(기본 해제·시각 기록·철회 시 총액만 파기).
- 금액 `EncryptedText`, `services/account_erasure` 명시 목록·`routes/profile.py` export 편입.
- 푸시: `NOTIFICATION_EVENT_IDS` 추가(기본 꺼짐), 크론 추가 시 `EXPECTED_JOB_COUNT` 수정, 본문에 금액 넣지 않음(잠금화면).
- **은행·카드 연동·문자 파싱으로 생활비 자동 채우기는 사전 BLOCK** — 마이데이터(본인신용정보관리업) 영역.

## 변호사(R1) 질문 — 서버 저장으로 옮기기 전에 확인

1. 기기에만 저장하고 운영자가 접근하지 않는 입력값이 개인정보 보호법상 운영자의 "처리"에 해당하지 않는다는 판단의 적정성.
2. 이용자가 직접 입력한 소득 + 본인 체결 기록 결합이 신용정보법상 개인신용정보인지, 우리가 신용정보제공·이용자인지(금융위 2023-04-03 회신 적용).
3. 기능 안 선택 입력 항목의 처리 근거: §15①4 로 충분한지, §15①1 별도 동의가 필수인지. 입력·저장 행위만으로 동의를 갈음할 수 있는지.
4. 이용자가 정한 금액 대비 체결 합계를 사후 통보하는 알림이 투자자문업(2024-08 개정 이후 개별 맞춤)에 해당하지 않는 문구의 한계선.
5. 이용자가 켠 월급날 리마인더 푸시의 정통망법 §50 정보성/광고성 구분.
6. (기존 공백) 웹푸시가 경유하는 브라우저 벤더 푸시 서비스의 처리방침 제6조 고지 필요 여부.
